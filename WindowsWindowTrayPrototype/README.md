# Windows 窗口与系统托盘验证原型

这是一个用于验证 PRD 中 Windows 窗口与托盘行为的独立原型，不是正式便签软件，不连接正式数据库，也不保存便签正文。

## 目标环境

- Windows 11 x64
- .NET 10 SDK
- WPF
- Windows Forms `NotifyIcon` 仅用于系统托盘

## 运行

在 Windows 11 x64 安装 .NET 10 SDK 后，在项目目录运行：

```powershell
dotnet --info
dotnet build .\WindowsWindowTrayPrototype.csproj
dotnet run --project .\WindowsWindowTrayPrototype.csproj
```

本原型未在本生成环境中运行。必须在真实 Windows 11 x64 环境编译和执行后，才能判断实际窗口行为是否通过。

## 已包含的验证操作

1. 创建单张便签或一次创建 20 张测试便签。
2. 检查独立便签是否出现在任务栏和 Alt+Tab。
3. 点击便签 X，检查是否只隐藏当前窗口。
4. 在管理中心显示、隐藏、定位便签。
5. 切换单张置顶。
6. 全局隐藏与恢复，并观察单张隐藏状态。
7. 托盘左键打开管理中心，右键菜单提供新建、全局隐藏/恢复、管理中心、快捷键设置和退出。
8. 管理中心 X 弹出“关闭应用 / 缩小到系统托盘 / 取消”。
9. 三个全局快捷键可启用/禁用、修改组合；注册失败时在日志中显示 Win32 错误码。
10. 在不同显示器和 DPI 缩放比例下拖动窗口，测试断屏找回。

## 默认全局快捷键

- `Ctrl+Alt+N`：新建便签
- `Ctrl+Alt+M`：打开管理中心
- `Ctrl+Alt+H`：全局隐藏/恢复

设置只保存在当前进程内，关闭程序后不会持久化。这是原型限制，不代表正式产品需求。

## 已知限制

- 不含正式业务逻辑、SQLite、自动保存、备份、恢复、归档、回收站或导出。
- 不实现完整的首次启动引导、登录自动启动和安装器。
- 窗口尺寸、位置算法及视觉样式仅用于原型验证。
- WPF 的 `ShowInTaskbar=false` 与工具窗口行为仍需在 Windows 11 实测，不应只根据源码判断通过。
- 全局快捷键的实际冲突情况依赖当前系统与其他正在运行的软件。
- 本原型的“显示全部”会显示所有测试窗口，包括之前单独隐藏的窗口；“全局隐藏/恢复”才用于测试记住原本可见集合的行为。

## 重要说明

这是用于降低技术风险的原型。原型在 Windows 11 x64 实际通过验收前，不应把窗口、托盘、快捷键或 DPI 行为标记为已验证。它也不冻结最终产品的 C# / Rust 语言分工。



隐藏状态组合

- [x] 单张便签原本隐藏 → 全局隐藏 → 全局恢复：原本隐藏的便签仍然隐藏。
- [ ] 全局隐藏期间，手动显示一张便签 → 全局恢复：不能意外显示其他便签。
- [ ] 全局隐藏期间，将一张原本可见的便签单独隐藏 → 全局恢复：该便签仍保持隐藏。

关闭、退出与重复启动

- [x] 主管理窗口 × 的三个选项分别产生正确结果。
- [ ]  托盘选择“退出软件”后，所有便签关闭、托盘图标消失、快捷键释放，进程真正退出。
- [ ] 软件已运行时再次启动，只激活现有实例，不创建第二个实例。

全局快捷键边界

- [x] 快捷键已被其他程序占用时，明确提示注册失败。
- [ ]  两个功能设置为相同组合时，不能静默地认为两者都可用。
- [ ] 修改、禁用和重新启用快捷键后，实际响应与设置一致。

多显示器与 DPI

- [x] 在 100% 与 150% 或 200% 缩放的显示器之间移动便签。
- [ ]  便签所在显示器断开、重新连接或分辨率变化后，便签仍能找回。
- [ ]  主管理窗口和便签不会跑到不可见区域，文字及控件仍然可用。

长时间运行与窗口层级

- [x] 同时显示 20 张便签，反复隐藏、显示、定位和置顶。
- [x] 电脑睡眠、唤醒后，便签与托盘仍然正常。
- [x]  管理中心被激活后，独立便签的置顶属性不会被意外修改。
