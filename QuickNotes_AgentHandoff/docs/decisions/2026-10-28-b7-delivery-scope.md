# ADR：B7 交付范围——文档与验证，不含 UI

- **日期：** 2026-10-28
- **状态：** 已接受（随 B7 实施记录）
- **范围：** B7 交付阶段
- **相关：** `docs/agent/Agent对接文档_B阶段.md` B7、`AGENTS.md`、B3/B4/B5/B6 ADR 与完成总结

## 背景

Agent 对接文档把 B7 定义为“交付”：可构建源码、可重复测试、README、数据模型与备份格式说明、四类 ADR、测试报告（通过/失败/未运行）、已知限制与下一阶段建议。B7 不包含产品 UI、宿主、快捷键、设备设置或安装器。

历史文档存在阶段编号歧义：

- B3 ADR D11 写“B7 再补齐设置/草稿策略”；
- B4 ADR 后续写“B7：UI/宿主集成、备份目录配置、草稿与设置策略”；
- B5 ADR 后续写“B7：UI 确认界面、设备设置/快捷键/显示器适配、恢复入口、首次运行恢复”；
- B6 完成总结的 B7 准备也沿用了 UI 表述。

这些表述与上游 B7 定义、以及 `AGENTS.md` “B 阶段不要实现完整 WPF 产品 UI、托盘、快捷键”冲突。若在 B7 实施 UI，会超出上游任务范围并改变交付性质。

## 决策

1. **B7 只做交付文档与验证。** 范围严格按 Agent 对接文档 B7 的七个交付项执行；不新增数据层/备份/恢复功能，不实现 UI、宿主、托盘、快捷键、安装器或设备设置。
2. **四类必需 ADR 的可查性。** SQLite 访问方式 → 新增 [B7 SQLite 访问方式汇总](2026-10-28-b7-sqlite-access.md)（细节服从 B2 ADR 与 B3 ADR D2）；备份格式 → B3 ADR；周备份规则 → B4 ADR；恢复切换 → B5 ADR。B7 新增 ADR 索引做映射，不改写既有决策正文。
3. **历史文档的“B7 UI/设置”表述视为阶段编号歧义。** UI、宿主、设备设置、首次运行恢复、schema 迁移、导出等进入 B 阶段之后的 **C 阶段**（或用户另行指定的阶段）；B7 不做这些工作，也不在文档中承诺已实现。
4. **B7 的验证标准是文档与实测一致。** 所有命令、测试数量、环境、未运行项必须以当前分支实测为准；不得把 B6 或更早结果冒充 B7 结果。
5. **不修改 PRD。** PRD 11.5 的完整字段要求保持不变；B7 在数据模型/限制文档中如实标注当前原型覆盖子集。

## 后果

**正面**

- B7 交付边界与上游文档、`AGENTS.md` 一致，不引入范围蔓延。
- 四类 ADR 有明确导航；历史决策不被重写。
- 测试报告与限制清单能真实反映 B 阶段能力，便于 C 阶段规划。

**负面 / 限制**

- B 阶段结束时仍没有可运行 UI/宿主；用户只能通过测试与类库验证数据层。
- PRD 11.5 的外观/窗口/设置/设备字段仍未实现，不能视为完整产品备份。
- 历史 ADR/总结中的“B7 UI”文字仍存在，本 ADR 作为统一澄清；如未来重排阶段编号，应整体更新文档而不是逐条改写历史记录。

## 备选方案

- **B7 实现 UI/宿主：** 超出上游 B7 定义与 `AGENTS.md` 的 B 阶段边界，且需要产品交互决策，拒绝。
- **改写 B3–B6 ADR 的“后续”段落：** 会篡改历史决策记录；改为新增本 ADR 澄清，拒绝直接改写。
- **不补 ADR 索引，直接交付 README：** 无法满足“ADR：SQLite 访问方式、备份格式、周备份规则、恢复切换”的可查性要求，拒绝。
- **把未运行的 UI/真实故障测试写成通过：** 违反 `AGENTS.md` 如实报告要求，拒绝。

## 验证

- `docs/decisions/README.md` 中四类必需 ADR 与文件一一对应。
- README、数据模型/格式、测试报告、限制文档互相链接且无死链。
- B7 全量构建/测试/漏洞审计结果与测试报告一致。
- 测试报告“未运行”明确列出 UI、真实卷耗尽/ACL/崩溃、WAL、跨进程、首次运行、schema 迁移等。
