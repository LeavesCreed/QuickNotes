# ADR：C2 编辑器保存时序、草稿保护与状态语义

- **日期：** 2026-10-28
- **状态：** 已接受（C2 实施前候选值，用户确认进入 C2 构建）
- **范围：** C2 最小编辑、自动保存与草稿保护
- **相关：** `docs/agent/Agent对接文档_C阶段.md` C2、PRD 10.1–10.3、B2 保存 ADR、C2 计划

## 背景

PRD 要求自动保存并区分“编辑中/保存中/已保存/保存失败”，但未规定去抖、最大延迟、草稿捕获频率和关闭时行为。B2 已提供真实保存语义：提交成功才报告 Saved；提交未知回读核验；BUSY/LOCKED 最多 3 次、最坏约 3.2–3.4 秒；草稿独立保存。C2 需要在不改变 B2 语义的前提下，为 UI 提供可测试、可预测的编辑状态。

## 决策

1. **草稿与数据库保存分离。** 每次编辑后草稿去抖 **300ms** 落盘；连续编辑最长 **2s** 至少落盘一次。草稿成功不等于保存成功，UI 分别显示。
2. **数据库自动保存。** 编辑停止后 **800ms** 触发自动保存；连续编辑最长 **5s** 强制一次保存；显式 Ctrl+S/保存按钮、焦点离开、切换便签、关闭窗口立即触发。
3. **每便签串行。** 每个编辑器 session 最多一个保存在进行；期间新快照排队，完成后仅保存最新快照。保存完成时比较快照序号：
   - 等于当前序号：显示 Saved，更新 BaseVersion；
   - 小于当前序号：只更新 BaseVersion/内部状态，保持 Modified，绝不把新编辑标为已保存；
   - 迟到结果不得覆盖新文本/新草稿。
4. **保存结果映射。**
   - `Saved` → Saved；新建便签转 IsNew=false。
   - `Conflict` → Conflict，保留本地快照与草稿；提供重载数据库版本/另存为新便签。
   - `OutcomeUnknown` → OutcomeUnknown，先回读数据库；匹配则确认 Saved，不匹配 Conflict，不存在则允许同 ID 重试创建。
   - `StorageUnavailable/ValidationFailed/NotFound` → SaveFailed；草稿保留，提供重试。
5. **草稿清理。** 草稿只在数据库保存成功且草稿内容匹配已保存快照时由 B2 清理；更新的草稿必须保留。草稿写入失败显示“内容尚未得到本地保护”，提供重试，不阻止数据库保存尝试。
6. **关闭/退出。** 窗口关闭先取消去抖并 `FlushDraftAsync`，再尝试 `SaveNowAsync`；成功关闭；失败/未知显示“重试 / 保留草稿退出 / 取消”，不静默丢弃。系统强制结束只保证已落盘草稿；未落盘窗口边界在人工清单说明。
7. **不新增保存语义。** 不修改 B2 的重试/提交/草稿清理规则；C2 只编排调用与 UI 状态，不直接 SQL。
8. **冲突不自动合并。** 首版只提供重载/另存，不做字段级或文本自动合并；保留双方内容。

## 后果

**正面**

- 编辑状态可预测、可测试；迟到结果不会误报已保存。
- 草稿独立保护，数据库失败/冲突/未知结果仍可恢复。
- 关闭/退出有明确保护路径，不依赖 UI 线程长时间阻塞。

**负面 / 限制**

- 自动保存最多可能有约 800ms 去抖 + B2 最长约 3.4s 的保存时延；UI 必须显示 Saving。
- 草稿去抖/最大延迟是产品体验候选值，不是 PRD 已冻结指标；人工检查可调整。
- 关闭时若用户选择保留草稿退出，数据库可能仍是旧版本；启动后需草稿恢复。
- 强制终止/断电无法保证最后 300ms 内输入落盘；只能保证已成功草稿。

## 备选方案

- **每次按键立即保存：** 写放大、锁竞争和 UI 压力大；拒绝。
- **只在失焦/关闭保存：** 崩溃损失窗口过大；拒绝。
- **草稿与保存同一任务：** 数据库失败会阻断草稿保护；违反分离呈现；拒绝。
- **冲突自动合并：** 容易静默覆盖；PRD 不允许；拒绝。
- **保存完成即认为最新：** 迟到结果会误报；拒绝。

- `EditorPersistenceIntegrationTests`：真实 SQLite/草稿的重开、草稿恢复、冲突、未知。
- WPF 人工清单：快速输入、保存中编辑、关闭/重试/保留草稿、冲突/未知 UI。
- 未运行项：真实强杀/断电、性能/长时间（C6）。
