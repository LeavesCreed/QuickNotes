# ADR：C1 桌面宿主、组合根与 A/B 集成

- **日期：** 2026-10-28
- **状态：** 已接受（随 C1 实施记录）
- **范围：** C1 桌面宿主与 B 数据层集成
- **相关：** `docs/agent/Agent对接文档_C阶段.md` C1、`docs/agent/C0-集成设计与风险.md`、B2/B3/B5 ADR

## 背景

A 阶段是独立 WPF 窗口/托盘原型，不连接数据层、不保存便签、没有单实例或正式启动流程。B 阶段是库 + 测试，没有 WPF 入口。C1 需要把两者接成一个可启动宿主，同时保持 Domain/Application 不依赖 WPF、UI 不直接操作 SQLite。

## 决策

1. **新增两个项目。** `QuickNotes.Desktop.Core`（net10.0，无 WPF）承载路径、单实例、应用状态、启动状态机、恢复日志读取、缺失库重建、持久写入门；`QuickNotes.Desktop.Wpf`（net10.0-windows，WinExe/UseWPF）只承载 App 生命周期、窗口和命令。另建 `QuickNotes.Desktop.Tests`（net10.0）测试 Core。
2. **依赖方向。** WPF → Core → Application/Infrastructure；Domain/Application 不引用 Desktop。WPF 不直接执行 SQL、不绕过 `INoteSaveCoordinator`/`IRestoreCoordinator`/`IDatabaseWriteGate`。
3. **组合根。** `App.OnStartup` 解析 `--data-root`/`--backup-dir`/`--single-instance-probe`，先取得单实例所有权，再创建数据路径、日志、状态存储、启动协调器；不引入 DI 容器，显式构造依赖。C1 不启动备份周期任务/编辑服务。
4. **A 原型处理。** 不搬迁、不修改 A 原型的窗口/托盘/快捷键代码；C1 新建宿主。A 的托盘、X 三选项、快捷键、置顶、多屏模式留 C5 复用/重写，A-11 失败项不得继承为已验证。
5. **UI 线程。** 启动、重建、单实例激活使用 async/await；不在 UI 线程同步等待数据库、命名管道或备份快照。UI 命令执行时禁用相关按钮，异常转日志 + 可诊断消息。
6. **C1 UI 范围。** 只提供启动/诊断窗口：状态、原因、路径、日志、恢复产物、选择已验证备份重建、重试检查、退出；不提供编辑器、设置、备份列表、托盘或快捷键。Ready 状态明确提示编辑器将在 C2 接入。
7. **测试边界。** Core 逻辑通过 Desktop.Tests 直接驱动；WPF 只做启动冒烟和人工检查；真实第二进程使用 `--single-instance-probe`。人工未执行项必须标记未运行。

## 后果

**正面**

- UI/业务边界清晰，数据层继续可独立测试。
- 宿主可复用既有保存/备份/恢复语义，不需要重写。
- 启动安全/单实例/重建逻辑可在无 WPF 环境中测试。

**负面 / 限制**

- C1 没有编辑器/托盘，试用需 C2/C5；C1 完成不等于产品可用。
- WPF 视觉、多屏/DPI、真实用户交互仍需人工/后续验证。
- 新增项目/解决方案配置增加构建面；C7 可能需要正式交付解决方案。

## 备选方案

- **直接扩展 A 原型：** 原型代码无数据边界、托盘与窗口耦合，改造成本和风险高；拒绝。
- **把宿主逻辑放 WPF 项目：** 难以自动化测试单实例/启动状态；拒绝。
- **引入 DI 容器/框架：** 当前依赖少，显式组合足够；不为原型引入框架。
- **UI 直接访问 SQLite：** 绕过保存/恢复/写入门，违反数据安全规则；拒绝。

## 验证

- `QuickNotes.Desktop.Tests`：宿主启动模式、单实例、路径/状态、重建、持久阻断、真实第二进程。
- WPF 构建/冒烟：`--data-root` 首次启动、退出重开、第二实例、诊断窗口。
- 既有 B 245 测试回归。
- 全量结果见 `C1-测试报告.md`。
