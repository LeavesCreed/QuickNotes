# C6 测试 Harness、隔离故障与性能门禁决策

**日期：** 2026-10-30\
**状态：** 已记录（C6 实施决策；性能验收仍开放，C6 未通过）\
**范围：** C6 真实故障、检查点强杀、恢复不变量、性能与长稳验证

## 背景

C6 需要验证真实存储/权限/离线故障、进程强杀后的重启恢复、第二实例竞争以及 1,000 历史/20 窗口性能。直接在生产代码加入测试分支、在用户数据根制造故障、或把注入式测试/短时 smoke 当成真实环境通过，都会破坏数据安全与验收可信度。

## 决策

1. **Test-only Harness 与 UiProbe**
   - 故障 Harness 与 WPF UiProbe 只存在于 `tests/`，引用真实生产宿主/服务；生产项目不加入 checkpoint、fault flag 或测试分支。
   - Harness 通过接口装饰器写检查点 marker；marker 只含阶段名和时间戳，不含便签正文、草稿内容或完整路径。
   - UiProbe 不构造 `App`，不创建托盘、全局热键、HKCU Run 或管理工作区；只用于性能/长稳测量。

2. **隔离故障资源**
   - 空间故障只允许临时 VHD（非系统卷、目录挂载、C6 RunId、创建者元数据）；ACL 故障只允许一次性临时目录，并捕获/恢复原始 SDDL + 写探针。
   - 强杀只针对带精确 C6 `--run-id` 的 Harness 进程树；驱动先校验命令行身份，从不按进程名枚举或终止用户进程。
   - 每个 run root 位于 `%TEMP%\QuickNotes-C6\<RunId>`；证据保留在 run root 之外，清理只删除带 RunId 的资源。

3. **性能预算与门禁**
   - 采用 C0 候选预算作为 C6 确认门禁（用户 2026-10-30 确认）：启动无 UI p95 2,000 ms、含 UI p95 3,000 ms、保存 p95 500 ms/p99 1,500 ms、输入 p95 100 ms、20 窗口工作集 300 MiB。
   - 只在 `C6_BUDGETS_CONFIRMED=1` 时比较预算；未确认时输出 `budgetStatus=unconfirmed`、`passed=false`，只记录基线。
   - 测量后不得修改阈值；超预算必须登记 finding 或书面风险接受。
   - 2 小时长稳必须是 60 s 采样、121 期望/120 最少样本、最大间隔 90 s、每样本 edit/save、峰值工作集门禁；3 分钟 smoke 不是长稳证明。15% 工作集/50 句柄增长仅作为未确认诊断，不设门禁。

4. **默认套件隔离**
   - 真实 ACL/VHD、真实强杀、真实恢复进程、WPF 性能与长稳不进入默认 `dotnet test`；默认套件只跑安全契约、服务级不变量和合成数据。
   - 真实用例由显式 PowerShell 驱动或 `C6_RUN_REAL_PROCESS_CASES=1` opt-in 执行，并在报告中给出确切命令和保留证据。

5. **状态语义**
   - PASS 必须有真实执行证据；NOT RUN 不得写成通过；注入式/短时 smoke 只能标记为对应范围。
   - 性能聚合在 UI 启动门禁失败或 2h 未运行时不得为 PASS；C6 整体在 C5-M/C6-M06 未完成或书面风险接受前不得通过。
   - 进程强杀不等于真实断电，临时 VHD/ACL 不等于所有硬件/文件系统；未测组合必须单列。

## 后果与限制

- C6 自动化可复现且默认开发机安全，但真实故障依赖显式驱动/提权环境；默认套件的 7 个 opt-in 跳过不是通过。
- 当前执行结果是：C6-F02/F03、C6-K01–K09、C6-M01–M05 自动化 PASS；C6-F01/F04/F05/F06、2h、C5-M/C6-M06 NOT RUN；性能聚合 FAIL（F-C6-PERF-01）。因此 C6 未通过验收，C7 未开始。
- 若后续为 F-C6-PERF-01 或真实故障修复生产代码，必须重跑全量测试、性能/长稳门禁与 WPF 冒烟。
- 导出、安装器、自动更新、备份加密、云存储、WAL/多实例写入不在 C6 范围。
