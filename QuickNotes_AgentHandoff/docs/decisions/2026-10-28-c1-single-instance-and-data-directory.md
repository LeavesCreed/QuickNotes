# ADR：C1 单实例、数据目录与日志

- **日期：** 2026-10-28
- **状态：** 已接受（随 C1 实施记录）
- **范围：** C1 单实例、正式数据目录、诊断日志
- **相关：** `docs/agent/Agent对接文档_C阶段.md` C1、PRD 8.4/11.1/17、`docs/agent/C0-集成设计与风险.md`

## 背景

B 阶段没有正式数据目录/日志/单实例；A 阶段原型也没有单实例。PRD 要求同一用户再次启动只激活现有实例，不在数据层未受保护时创建第二写入者。C1 必须在打开数据库、草稿或后台任务前取得实例所有权，并区分首次运行与已初始化但库缺失。

## 决策

1. **数据根。** 默认 `%LOCALAPPDATA%\QuickNotes\`；测试/手动用 `--data-root <dir>` 覆盖。目录内：`notes.db`、`drafts/`、`logs/`、`application-state.json`、`recovery-journal.json`。备份目录不在 C1 配置；`--backup-dir` 只用于诊断扫描保护快照/临时产物，C4 再做正式选择。
2. **单实例范围。** 命名对象包含当前用户身份与规范化数据根 SHA-256 前 16 位；同一用户同一数据目录一个实例，不同数据根可并行（测试隔离）。
3. **机制：数据根锁文件 + 命名管道激活。** 第一实例在 `%LOCALAPPDATA%\QuickNotes\.quicknotes-instance.lock` 上以 `FileShare.None` 持有排他文件句柄，进程存活期间一直持有；第二实例无法取得排他句柄时不打开任何数据资源，连接命名管道发送 `ACTIVATE`。成功则第一实例激活窗口/退出第二实例；超时或管道不可用则明确提示“已有实例但无法激活”并退出。不得为第二实例创建 DB/草稿/日志写入。
4. **所有权顺序。** `SingleInstanceGuard.StartAsync` 在路径/状态/日志/数据库/草稿/后台任务之前；只创建数据根目录和锁文件，锁文件不是便签/草稿/备份数据。取得锁后才创建 DiagnosticLog、启动检查和服务。OS 在进程退出/崩溃后释放锁句柄；遗留锁文件本身不代表实例仍存活，下一次启动可安全重新打开。`--single-instance-probe` 只执行所有权/激活并退出，不打开数据，用于真实第二进程测试。
5. **为何不用命名 Mutex。** Windows 命名 Mutex 是线程亲和/可递归的：异步启动/退出可能在不同线程释放失败，同进程两个测试 guard 也可能因同线程递归而误判为第二 owner；这会让启动安全依赖 UI 线程细节。锁文件提供进程级所有权，跨线程/跨进程语义稳定，且同样在数据资源之前取得。命名管道仅用于激活，不承担所有权。
6. **诊断日志。** `logs/quicknotes-yyyyMMdd.log`，追加写；每条记录 UTC 时间、级别、事件名、错误码/摘要；不记录便签正文/草稿内容。日志写入失败不阻止启动，但 UI 显示“日志不可用”警告。
7. **首次运行与缺失。** 数据根不存在/空且无任何数据证据才允许首次初始化；`application-state.json` 与数据库必须分别判断。已初始化但数据库缺失、数据库存在但状态缺失、状态损坏均不得自动建空库（详见启动恢复 ADR）。
8. **备份目录边界。** C1 不修改/创建用户备份目录，不把数据根与备份目录合并；`--backup-dir` 只读扫描。C4 实现首次备份目录选择、可写验证和绑定。

## 后果

**正面**

- 单实例先于数据资源，避免两个进程同时写入 SQLite。
- 数据/日志/状态路径明确，测试可通过临时根隔离。
- 诊断日志不泄露正文，便于启动/恢复排障。
- 备份目录配置留 C4，避免 C1 偷偷改变用户设置。

**负面 / 限制**

- 单实例依赖文件共享语义与命名管道激活；管道故障时第二实例只能明确退出，不能保证激活成功。
- `%LOCALAPPDATA%` 与用户身份作用域只覆盖同用户/同会话；跨用户/服务场景不承诺。
- 锁文件会留在数据根（无害）；不用于判断进程存活，只以能否取得排他句柄为准。
- C1 无备份目录配置，保护快照扫描只有在 `--backup-dir` 下才能覆盖。
- 日志文件无自动轮转/保留策略；C7/后续需完善。

## 备选方案

- **命名 Mutex：** 线程亲和/可递归，异步启动/退出和测试中容易误判；拒绝。
- **只靠锁文件，不做激活：** 第二实例只能退出，不能激活现有实例；不满足 PRD；拒绝。
- **Global 命名对象：** 影响其他会话/权限面更大；当前单用户桌面不需要。
- **数据根放 ProgramData/安装目录：** 需要权限/安装决策，C1 不引入；拒绝。
- **C1 同时做备份目录设置：** 属于 C4，且首次配置有产品交互规则；拒绝提前。

## 验证

- 单实例单元 + 真实第二进程测试：第二实例激活、激活失败明确退出、不同数据根不冲突。
- 路径/状态/日志测试：默认/覆盖根、原子写、日志追加、无正文。
- 手动：首次启动、第二实例、退出重开、诊断窗口路径。
- 未运行：跨用户/跨会话、管道被防火墙/权限拦截、真实崩溃。
