# ADR：C1 单实例、数据目录与日志

- **日期：** 2026-10-28
- **状态：** 已接受（随 C1 实施记录）
- **范围：** C1 单实例、正式数据目录、诊断日志
- **相关：** `docs/agent/Agent对接文档_C阶段.md` C1、PRD 8.4/11.1/17、`docs/agent/C0-集成设计与风险.md`

## 背景

B 阶段没有正式数据目录/日志/单实例；A 阶段原型也没有单实例。PRD 要求同一用户再次启动只激活现有实例，不在数据层未受保护时创建第二写入者。C1 必须在打开数据库、草稿或后台任务前取得实例所有权，并区分首次运行与已初始化但库缺失。

## 决策

1. **数据根。** 默认 `%LOCALAPPDATA%\QuickNotes\`；测试/手动用 `--data-root <dir>` 覆盖。目录内：`notes.db`、`drafts/`、`logs/`、`application-state.json`、`recovery-journal.json`。备份目录不在 C1 配置；`--backup-dir` 只用于诊断扫描保护快照/临时产物，C4 再做正式选择。
2. **单实例范围。** 命名对象包含当前用户 SID（获取失败用用户名）与规范化数据根 SHA-256 前 16 位；使用 `Local\` 命名空间，同一用户同一数据目录一个实例。不同数据根可并行（测试隔离）。
3. **机制。** 第一实例持有命名 Mutex，并启动命名管道服务器；第二实例未取得 Mutex 时不打开任何数据资源，连接管道发送 `ACTIVATE`。成功则第一实例激活窗口/退出第二实例；超时或管道不可用则明确提示“已有实例但无法激活”并退出。不得为第二实例创建 DB/草稿/日志写入。
4. **所有权顺序。** `SingleInstanceGuard.StartAsync` 在路径/状态/日志/数据库/草稿/后台任务之前；第一实例启动管道后，才创建 DiagnosticLog（日志本身也不应在第二实例打开）。`--single-instance-probe` 只执行所有权/激活并退出，不打开数据，用于真实第二进程测试。
5. **诊断日志。** `logs/quicknotes-yyyyMMdd.log`，追加写；每条记录 UTC 时间、级别、事件名、错误码/摘要；不记录便签正文/草稿内容。日志写入失败不阻止启动，但 UI 显示“日志不可用”警告。
6. **首次运行与缺失。** 数据根不存在/空且无任何数据证据才允许首次初始化；`application-state.json` 与数据库必须分别判断。已初始化但数据库缺失、数据库存在但状态缺失、状态损坏均不得自动建空库（详见启动恢复 ADR）。
7. **备份目录边界。** C1 不修改/创建用户备份目录，不把数据根与备份目录合并；`--backup-dir` 只读扫描。C4 实现首次备份目录选择、可写验证和绑定。

## 后果

**正面**

- 单实例先于数据资源，避免两个进程同时写入 SQLite。
- 数据/日志/状态路径明确，测试可通过临时根隔离。
- 诊断日志不泄露正文，便于启动/恢复排障。
- 备份目录配置留 C4，避免 C1 偷偷改变用户设置。

**负面 / 限制**

- 单实例依赖命名管道激活；管道故障时第二实例只能明确退出，不能保证激活成功。
- `%LOCALAPPDATA%` 与用户 SID 作用域只覆盖同用户/同会话；跨用户/服务场景不承诺。
- C1 无备份目录配置，保护快照扫描只有在 `--backup-dir` 下才能覆盖。
- 日志文件无自动轮转/保留策略；C7/后续需完善。

## 备选方案

- **文件锁代替 Mutex：** 需要在数据目录打开文件，违反“先取得所有权再打开数据资源”的顺序；拒绝。
- **只靠 Mutex，不做激活：** 第二实例只能退出，不能激活现有实例；不满足 PRD；拒绝。
- **Global 命名对象：** 影响其他会话/权限面更大；当前单用户桌面不需要。
- **数据根放 ProgramData/安装目录：** 需要权限/安装决策，C1 不引入；拒绝。
- **C1 同时做备份目录设置：** 属于 C4，且首次配置有产品交互规则；拒绝提前。

## 验证

- 单实例单元 + 真实第二进程测试：第二实例激活、激活失败明确退出、不同数据根不冲突。
- 路径/状态/日志测试：默认/覆盖根、原子写、日志追加、无正文。
- 手动：首次启动、第二实例、退出重开、诊断窗口路径。
- 未运行：跨用户/跨会话、管道被防火墙/权限拦截、真实崩溃。
