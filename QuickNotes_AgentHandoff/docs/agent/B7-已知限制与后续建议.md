## 1. 产品与功能范围

### 1.1 当前不提供

- 完整 WPF 界面、托盘、快捷键、单实例宿主、安装器。
- 便签编辑 UI、草稿恢复 UI、保存失败提示 UI。
- 手动备份 UI、手动备份删除确认、备份目录配置界面。
- 整库恢复确认界面（备份时间/来源/版本/数量/替换说明）与恢复进度。
- 首次运行初始化、当前数据库缺失时的恢复、启动时遗留 staging 清理。
- schema 迁移/升级保护（PRD 11.8）；当前只支持 schema v1。
- TXT/Markdown/JSON/ZIP 导出（PRD 12）。
- 设备设置、快捷键、开机启动、显示器标识的保存与跨设备适配。
- 备份加密、压缩包密码、云同步。

### 1.2 数据模型相对 PRD 11.5 的差距

当前 schema 只包含便签、分类、标签、标签关联及便签的基础状态。PRD 11.5 要求但**尚未建模/未进入备份包**的内容：

- 便签颜色、字号、默认/覆盖模式；
- 窗口位置、尺寸、显示/隐藏、置顶之外的窗口状态；
- 全局隐藏恢复所需状态；
- 应用设置、顶栏配置；
- 当前设备专属配置（备份目录、开机启动注册状态、显示器标识）。

因此当前备份包不是 PRD 意义上的“完整应用备份”，只是数据层一致快照。草稿、窗口布局、应用设置与设备配置不在包内。

### 1.3 阶段边界澄清

历史 B3/B4/B5/B6 文档曾把“UI/设置/宿主”写作 B7 的后续工作；按上游 Agent 对接文档，B7 仅做交付文档与验证，UI/设置/宿主进入 B 阶段之后的 C 阶段。该歧义已由 [B7 交付范围 ADR](../decisions/2026-10-28-b7-delivery-scope.md) 统一澄清。

## 2. 技术限制

### 2.1 保存与 SQLite

- 应用层最多 3 次 BUSY/LOCKED 尝试，加退避最坏约 **3.2–3.4 秒**；不是规格草案中的约 950ms。UI 需按此设计“保存中”状态。
- Microsoft.Data.Sqlite 仍可能在 COMMIT 上内部重试最多约 1 秒；应用层不会重跑整次保存，提交未知仍回读核验。
- 未启用 WAL；读写并发仍可能遇到 BUSY/LOCKED。
- 单进程/单实例假设；无跨进程保存、备份或恢复锁。
- `SqliteConnectionFactory` 的 `configureConnection` 钩子可执行任意连接级命令；它是为故障注入提供的测试接缝，默认 `null`，不应由业务层滥用。

### 2.2 备份与留存

- 在线备份 API 同步且不支持中途取消；取消只保证发布前不产生最终包，不保证立即中断复制。
- 备份耗时、ZIP 压缩/解压校验开销随数据库增长；无进度 UI。
- 备份包未加密；只包含 `notes.db` + `manifest.json`，不含草稿/设置/设备配置。
- manifest/数据库解压上限默认 4 GiB；超过上限拒绝，未针对超大库做分片/增量备份。
- SQL 指纹是启发式：标签/分类重命名或删除若计数、名称长度和、`MAX(modified_at_utc)` 都不变，可能漏检；需要扩展指纹或改为持久化变更计数器。
- 状态文件与备份目录同处；状态缺失/损坏在当日无有效日备份时会导致一次多余日备份（安全但非最小）；状态写入失败会返回警告，下一次可能重复备份。
- 调度档只做轻量校验：包创建后若静默损坏且大小不变，调度可能仍认为今日已有备份；留存档会用哈希排除，恢复会重新完整校验。
- 删除失败只记录警告并继续；不会自动重试删除。
- 备份目录不可用/权限失败依赖调用方重试；B4 服务本身不包含宿主调度器（推荐 15 分钟并在启动时立即检查）。

### 2.3 恢复

- 只支持 schema v1；不迁移、不半迁移。不兼容版本直接拒绝。
- 当前数据库必须存在；首次运行/当前库缺失的恢复未实现。
- 当前库存在 `-journal`/`-wal`/`-shm` 时，准备/切换会拒绝或恢复热 journal；不支持 WAL 库的恢复。
- `File.Replace` 依赖 Windows 与当前库同卷 staging；跨卷恢复不支持。
- 恢复需要额外空间：staging 恢复库 + 回退副本 + 保护快照；空间不足在预检拒绝。
- 恢复期间保存被共享写入门阻塞；大库可能长时间显示“恢复中”。
- 回退失败会阻断后续写入并保留保护/回退/staging；解除阻断需要重启/人工处理，当前无自动修复入口。
- 保护快照不包含草稿；恢复保留草稿目录，但不把草稿纳入整库替换。
- 崩溃可能遗留 `.quicknotes-restore-*` 或 `.quicknotes-tmp-*` 目录；当前无启动清理。
- 恢复完成后只核对 hash/counts/schema/完整性/外键；不逐字段比较全部内容（staged DB 即包内 DB，已通过包哈希）。

### 2.4 故障注入与测试边界

- B6 用 `PRAGMA max_page_count`、只读文件、文件锁、只读留存包与接口装饰器覆盖失败语义；**不等于**真实耗尽磁盘卷、系统级 ACL、强杀进程/断电。
- 只读属性与 `FileShare.None` 行为依赖 Windows。
- 本次只执行一次全量套件；未做重复运行稳定性统计、性能/浸泡测试或代码覆盖率收集。
- 未运行项详见 [B7 测试报告](B7-测试报告.md) 第 6 节。

### 2.5 技术与产品状态

- SQLite 与 .NET 10 + WPF 仍是候选方向，最终技术选型尚未完全冻结；B 阶段不引入 Rust FFI。
- 应用无正式数据目录/日志/安装/升级路径；当前类库由测试或未来宿主自行组合。
- 备份与草稿文件未加密；单用户原型假设。

## 3. 待决事项

以下需要产品或技术决策，B7 不擅自决定：

1. C 阶段 UI/宿主架构：WPF 单实例、托盘、快捷键、编辑器与草稿恢复交互。
2. 设置模型：应用设置、窗口布局、便签外观、设备专属配置的 schema 与备份包含策略。
3. schema v2 迁移方案：迁移前保护快照、失败回滚、版本拒绝/兼容矩阵。
4. 首次运行与当前库缺失恢复：初始化、保护快照、用户确认。
5. 备份加密、压缩策略、超大库分片/增量；是否纳入首版。
6. 是否启用 WAL、是否支持多进程/多实例，以及相应的备份/恢复锁协议。
7. 真实故障环境验收：卷耗尽、ACL、崩溃/断电、长时间运行与性能预算。
8. 错误 UX：保存失败、恢复失败、回退失败阻断写入时的用户指引与恢复入口。

## 4. 下一阶段建议（按优先级）

| 优先级 | 建议 | 理由 |
|---|---|---|
| P0 | C 阶段宿主/UI 集成：编辑、草稿恢复、保存状态、恢复确认/进度、备份目录配置 | B 阶段只有类库；产品可用性依赖宿主 |
| P0 | 启动恢复与清理：首次运行初始化、遗留 staging 清理、回退失败阻断状态的恢复入口 | 崩溃/中断后的可恢复性缺口 |
| P1 | schema v2：便签外观、窗口布局、应用设置；迁移前保护快照与迁移测试 | PRD 11.5/11.8 的完整备份与升级保护 |
| P1 | 真实故障环境与稳定性：卷耗尽、ACL、强杀/断电、浸泡/性能、重复运行 | B6 注入不能替代真实环境验收 |
| P2 | 备份增强：加密、超大库分片/增量、手动备份管理 UI | 安全与规模需求 |
| P2 | WAL/多实例评估与跨进程锁 | 当前单进程假设限制产品形态 |
| P3 | 导出（TXT/Markdown/JSON/ZIP）、安装器、升级/卸载、诊断日志 | PRD 后续范围与交付工程化 |
