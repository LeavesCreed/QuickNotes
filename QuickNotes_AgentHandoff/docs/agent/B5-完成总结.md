## 2. 范围与边界

**本阶段包含**

- `RestoreCoordinator`：预检、保护快照、staging、切换、校验、回退、写入门阻断、结果映射
- `IDatabaseWriteGate` / `DatabaseWriteGate`：保存与恢复共享串行门；回退失败 `BlockWrites`
- `BackupPackageVerifier.ExtractAsync`：staging 提取 + 完整校验（复用 B3 逻辑）

- `DriveInfoDiskSpaceProvider`
- 预检/结果/错误契约
- 单元、SQLite 集成、端到端测试

**本阶段不包含**

- UI/确认界面、设备设置/快捷键/显示器适配（B7）
- schema 迁移/升级（B5 仅支持 v1；不兼容拒绝）
- 跨备份合并、WAL、B3/B4 格式/留存变更
- 真实磁盘满/权限/崩溃故障注入（B6）
- 首次运行/当前库不存在时的恢复

## 4. 关键流程

```text
预检（只读）
  - 包存在；B3 extractor 完整校验 ZIP/manifest/SHA-256/大小/DB 完整性/外键/schema
  - 备份与当前 schema 必须为 1；当前库存在/可读；无 -wal/-shm
  - 备份目录/当前库目录可写；空间（当前卷 staging+回退+同卷保护快照；备份卷保护快照）
  - 草稿检查：有草稿未允许则阻止；草稿检查失败阻止
  -> 获取恢复写入门（等待在途保存）
  -> PrepareCurrent（读写打开恢复热 journal；拒绝 WAL sidecar）
  -> B3 Manual 保护快照（成功且校验）
  -> 同卷 staging：提取包 DB + 完整校验 + counts
  -> 切换前取消检查
  -> File.Replace(staged, current, rollback)
  -> 当前库 hash + integrity/外键/schema/counts 对比 staged
  -> 成功：清理 staging/回退副本；保留保护快照；释放门
  -> 失败：File.Replace(rollback, current, failed) 回退并核对旧 hash/counts
       -> 回退成功：失败结果 + RolledBack=true
       -> 回退失败：BlockWrites + WritesBlocked=true；保留保护/回退/staging；恢复提示
```

- 切换后使用 `CancellationToken.None`；切换后不因随后取消谎报失败。
- 保护快照无论后续成功/失败都保留。
- 当前库有 `-journal`/`-wal`/`-shm` 时切换中止；热 journal 在恢复门内恢复。
- 保存与恢复共享写入门；恢复期间保存等待；回退失败后续保存返回 `StorageUnavailable` + `database_writes_blocked`。

## 6. 审查与修复

- [严重] 切换抛错后仅凭 counts/schema 相同就报成功 → 现在同时校验当前库 SHA-256 等于包 manifest 哈希；counts 相同但内容不同会判定切换失败，不误报成功。
- [严重] 切换后 `TryInspect`/回退抛出非 `RestoreException` 会直接外抛 → 现在 inspection/rollback 捕获非取消异常；切换后兜底 `BlockWrites` 并返回 `RollbackFailed`/`WritesBlocked`，保留恢复文件。
- 修复保护快照空间按当前库大小（而非备份包大小）估算；同卷时合并 staging/回退/保护需求。
- 预检增加当前库目录写权限探测；切换前再次检查 `-journal`/`-wal`/`-shm`；`ExtractAsync` staging 错误改为 `DestinationUnavailable`；回退路径单独校验与错误码。
- staging 目录在 Windows 标记 Hidden；意外异常日志只记录类型，不记录完整路径。
- 测试补充：切换失败同 counts 不同内容、暂存后取消、sidecar 切换、标签/生命周期/关联端到端校验。
- 保留建议：`RestoreCoordinator` 较长且预检/staging 有重复提取流程；崩溃遗留 staging 清理、真实系统级故障注入留 B6；无 UI 确认界面。

## 7. 已知限制

- 当前库必须存在；首次运行/当前库缺失的恢复留后续。
- B5 只支持 schema v1；不迁移/升级；不兼容版本拒绝。
- 恢复门会阻塞保存（含 staging/保护），大库恢复需要 UI 显示“恢复中”。
- `File.Replace` 依赖同卷与平台；staging/回退副本与当前库同卷。
- 切换后只校验 hash/counts/schema/完整性/外键；不逐字段比较（staged DB 即包内 DB，已通过哈希）。
- 单进程写入门；无跨进程恢复锁。
- 真实磁盘满/权限/崩溃/恢复中断/回退失败注入留 B6；崩溃遗留 staging 目录需后续清理。
- 无 UI 确认界面；预检结果供未来 UI 使用。
- 恢复不修改草稿/状态文件/设备设置；快捷键/启动/显示器适配留 B7。
