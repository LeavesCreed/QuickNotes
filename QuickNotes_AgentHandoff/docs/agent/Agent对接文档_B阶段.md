# Agent 对接文档：B 阶段数据存储与备份原型

**版本：** 1.0\
**阶段：** B --- 数据存储与备份原型\
**平台目标：** Windows 11 x64\
**目标原则：** 数据正确性与可恢复性优先于开发速度

## 1. 当前项目状态

-   产品基线：`docs/product/PRD_v1.0.md`。
-   A 阶段窗口/托盘原型用户反馈基本验证通过；不能据此推断所有
    DPI、断屏、单实例和异常路径均通过。
-   `.NET 10 + WPF` 是当前桌面候选；B 阶段可用 C# + SQLite 做数据验证。
-   技术选型尚未完全冻结。Rust 可以后续引入；当前不做 Rust FFI。
-   本阶段不开发完整便签 UI、托盘、快捷键、安装器或正式导出功能。

## 2. 必须回答的技术问题

1.  数据模型能否表达便签、分类、标签、归档和回收站？
2.  事务能否避免半提交？旧写入能否避免覆盖新内容？
3.  如何从正在使用的 SQLite 数据库生成一致性快照？
4.  如何实现每日有变化才备份、7 份日备份 + 4 份周备份？
5.  手动备份如何排除自动清理？
6.  恢复前如何预检，失败时如何保护并回退原库？
7.  如何自动化测试写入失败、备份损坏、恢复中断和清理失败？

## 3. 任务顺序与验收

### B0 --- 仓库和环境检查

**工作：** - 检查现有仓库、文件、SDK、测试框架和 SQLite 依赖。 - 检查
`dotnet --info`、目标框架与构建环境。 -
不覆盖现有文件；发现冲突先报告。 -
输出环境报告、缺失项、实施计划和风险。

**验收：** 环境已检测与未检测清楚区分；没有擅自覆盖用户文件。

### B1 --- 最小数据模型与 SQLite 持久化

**建议模型：** - `Note`：ID、可空标题、正文、创建/修改 UTC
时间、版本号、生命周期状态、主分类 ID、置顶、显示意图及必要外观字段。 -
`Category`：ID、名称、默认颜色。 - `Tag`：ID、名称。 -
`NoteTag`：便签与标签关联。 -
`AppSettings`：仅存必要设置；设备专属设置需单独识别。 -
窗口布局字段可以先做原型字段，不要过度建模。

**实现：** - 稳定唯一主键；所有时间戳 UTC 保存。 -
开启并测试外键约束。 - 关联修改使用事务。 - schema 有明确版本号。 -
更新具备版本检查或等效并发保护，旧写入不得静默覆盖新版本。 -
数据层不得依赖 WPF。 - 用临时目录进行集成测试。

**验收：** - 创建、读取、更新、状态变更可持久化。 -
外键和分类/标签关系正确。 - 注入事务失败后无半提交关联数据。 -
过期版本更新被拒绝或进入明确冲突路径。 -
关闭并重新打开数据库后数据一致。 - `PRAGMA integrity_check`
通过，外键检查无意外结果。

### B2 --- 保存协调与失败语义

-   只有事务提交成功后才报告保存成功。
-   错误可诊断；不吞异常。
-   为 UI 草稿保护提供清晰接口，但不开发编辑 UI。
-   测试写入失败、重试和旧写入覆盖保护。

### B3 --- 一致性备份快照

-   不得仅复制正在使用的 SQLite 主文件并声称获得可靠快照。
-   采用 SQLite 支持的一致性备份方式，并记录技术决策。
-   原型可采用"数据库快照 + manifest + 校验信息"的备份包。
-   manifest 至少记录格式版本、schema
    版本、创建时间、备份类型、文件大小和校验值。
-   先写临时文件，校验成功后才标记为正式备份。
-   测试磁盘不足、无权限、取消和中断；源库必须保持可用。

### B4 --- 自动备份与留存

**不可更改的产品规则：** - 每日有数据变化时备份。 - 保留 7 份日备份和 4
份周备份。 - 手动备份默认不参与自动清理。 -
当日无变化时不生成不必要的重复日备份。 - 备份失败不算当天成功。 -
新备份通过校验后才可清理超额自动备份。 -
同一物理文件兼任日/周备份时不得重复计数。

**需要写 ADR 的技术细节：** - 周起始日与周代表备份选择规则。 -
系统时钟/时区变化处理。 - 备份目录不可用后的重试策略。 -
留存元数据损坏时的保守处理。

**可供验证的候选策略：** 使用本机当地日历日、ISO
周（周一开始），每周代表备份取该周最近一次通过校验的日备份。必须记录为技术决策，不能悄悄改变
PRD。

### B5 --- 整库恢复与回退

-   恢复前检查文件、manifest、校验值、格式/schema
    版本、数据库完整性和关联完整性。
-   临时位置准备并校验恢复库；防范归档路径穿越。
-   切换前创建当前数据保护快照。
-   切换失败时回退；回退失败时停止进一步写入，保留原库、保护文件和错误信息。
-   不实现跨备份自动合并。
-   不盲目覆盖当前设备的备份目录、开机启动状态和显示器标识。

**验收：** - 损坏/校验失败的备份被拒绝，当前库不变。 -
恢复中断后原库仍可打开。 - 恢复成功后便签、分类、标签关系和状态一致。 -
所有失败路径不报告成功。

### B6 --- 故障注入测试

至少覆盖： - 数据库写入失败。 - 磁盘空间不足/写入拒绝。 -
备份取消或中断。 - 备份损坏或 checksum 不匹配。 - 恢复临时准备失败。 -
恢复切换失败和回退。 - 留存清理失败。 - 备份目录不可用。 -
旧写入与新写入竞争。

测试必须使用合成数据和临时目录。

### B7 --- 交付

-   可构建原型源码。
-   可重复执行的自动化测试。
-   README 运行说明。
-   数据模型和备份格式说明。
-   ADR：SQLite 访问方式、备份格式、周备份规则、恢复切换。
-   测试报告分开列出通过/失败/未运行。
-   已知限制和下一阶段建议。

## 5. 建议接口边界

-   `INoteRepository`：CRUD、状态变更、版本检查。
-   `IUnitOfWork` 或等效事务边界。
-   `IBackupService`：创建与校验备份。
-   `IBackupRetentionPolicy`：计算保留集合，不直接删文件。
-   `IRestoreService`：预检、准备、切换、回退。
-   `IClock`：可测试日期/周边界。
-   仅在有实际测试价值时引入 `IFileSystem`。

## 6. 可直接交给编码 Agent 的第一条提示词

> 先阅读仓库根目录 `AGENTS.md`、`agent.md`、`docs/product/PRD_v1.0.md`
> 和 `docs/agent/Agent对接文档_B阶段.md`。
>
> 只执行 B0 和 B1：检查仓库与环境，然后实现最小数据模型、SQLite
> schema、schema 版本、事务化 CRUD、版本冲突保护和集成测试。
>
> 先输出环境检查结果、实施计划和风险，再开始修改。不要实现完整 WPF
> UI、托盘、快捷键、自动备份轮换或整库恢复。不要引入 Rust
> FFI。只使用临时测试目录与合成数据，不访问真实用户数据。不得修改 PRD
> 已确认规则。
>
> 完成后运行构建和测试，如实报告通过/失败/未运行；列出变更文件、测试命令、限制、未解决问题和下一步建议。未执行的测试不得写成通过。

## 7. 阶段完成标准

-   事务和版本保护测试通过。
-   一致性备份可创建并校验。
-   7 日 + 4 周留存规则经过测试。
-   手动备份不被自动清理。
-   损坏备份与恢复失败不破坏当前数据。
-   关键故障路径有自动化测试。
-   Windows 11 x64 实测情况如实记录。
-   技术决策和风险已文档化。
