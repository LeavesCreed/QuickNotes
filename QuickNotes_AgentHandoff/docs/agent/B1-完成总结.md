## 4. 数据模型与 schema

### 4.1 领域模型

- `Note`：稳定 `Guid` 主键、可空标题、正文、创建/修改 UTC 时间、`Version`、`Lifecycle`、`CategoryId`、`IsPinned`、`DisplayIntent`。
- `Category`：ID、名称、默认颜色、是否系统内置；内置"未分类"ID 固定为 `6f2a98f2-20de-4f4e-a2f4-8a570c4625d7`。
- `Tag` / `NoteTag`：标签及便签-标签多对多关联。
- 枚举：`NoteLifecycle` 为 Active=0 / Archived=1 / Trash=2；`NoteDisplayIntent` 为 Hidden=0 / Visible=1。

### 4.2 表与约束

| 表 | 关键列与约束 |
|---|---|
| `categories` | `id` 主键；`name` 非空、`NOCASE` 唯一；`default_color` 非空；`is_system` 仅 0/1 |
| `tags` | `id` 主键；`name` 非空、`NOCASE` 唯一 |
| `notes` | `id` 主键；`title` 可空；`body` 非空；UTC 时间文本；`version >= 1`；`lifecycle` 仅 0/1/2；`category_id` 外键 `ON DELETE RESTRICT`；`is_pinned` 仅 0/1；`display_intent` 仅 0/1；`CHECK (lifecycle = 0 OR display_intent = 0)` |
| `note_tags` | 复合主键 `(note_id, tag_id)`；两个外键均 `ON DELETE CASCADE` |

索引：`notes(category_id)`、`notes(modified_at_utc DESC)`、`note_tags(tag_id)`。

### 4.3 初始化与连接

- `SqliteSchema.InitializeAsync` 在事务中建表、种子"未分类"分类，并设置 `PRAGMA user_version=1`。
- 版本 0 执行初始化；版本 1 直接复用；版本大于 1 或其他非零值抛出 `NotSupportedException`，不静默降级。
- 每个连接打开时执行 `PRAGMA foreign_keys=ON`；连接字符串使用 `Pooling=False`。
- 时间戳统一归一化为 UTC，并以 invariant `"O"` 格式存储；GUID 以 `D` 格式存储。

## 5. 关键行为与不变量

- **创建**：便签与标签关联在同一事务中写入；任一步失败均不留下半提交数据；新便签固定为 `Active`、`Version=1`。
- **读取**：按 ID 返回便签或 `null`；标签 ID 按序返回。
- **更新**：使用 `WHERE id = $id AND version = $expected_version` 原子更新，成功后 `version + 1`；标签关联在同一事务中整体替换。
- **冲突**：受影响行数为 0 时，在事务内区分"便签不存在"（`KeyNotFoundException`）与"版本过期"（`NoteConcurrencyException`，包含 `NoteId` 与 `ExpectedVersion`）。
- **状态变更**：`SetLifecycleAsync` 同样做版本检查，递增版本，并强制 `display_intent = 0`（归档/回收站不可见）。
- **提交语义**：所有写操作只有在事务提交成功后才返回；异常不被吞掉。
- **关联失败回滚**：向不存在的标签写入关联会触发外键错误，内容、版本与旧标签关联一起回滚（已有测试覆盖）。

## 11. B2 准备：保存协调与失败语义

B2 的目标（来自 `docs/agent/Agent对接文档_B阶段.md`）：

- 只有事务提交成功后才报告保存成功
- 错误可诊断，不吞异常
- 为 UI 草稿保护提供清晰接口，但不开发编辑 UI
- 测试写入失败、重试和旧写入覆盖保护

### 11.1 B1 已具备的基础

- 写操作在提交成功后才返回；异常未被吞掉。
- 过期版本更新已被 `NoteConcurrencyException` 拒绝。
- 关联失败会整体回滚。
- 已有临时数据库与故障场景（外键失败、版本冲突）测试基础。

### 11.2 B2 需要补齐的能力

1. **统一错误语义**：区分不存在、版本冲突、输入/约束错误、存储不可用、提交结果未知；避免上层看到原始 `SqliteException` 文本。
2. **忙碌/锁定与重试**：明确 `SQLITE_BUSY`/`SQLITE_LOCKED` 的等待与重试策略（`busy_timeout`、退避、最大次数），并保证不可盲目重试非幂等写入。
3. **提交结果未知**：提交抛异常时不得报告成功；需提供可诊断的结果或异常，并说明如何核验实际状态。
4. **UI 草稿保护接口**：在 Application 层定义清晰的草稿保存/恢复契约，用测试替身验证，不开发编辑器 UI。
5. **故障注入测试**：写入失败、锁定/忙碌、重试成功、重试耗尽、回滚、提交歧义等路径需要可重复的集成测试。
6. **可诊断信息**：异常/结果携带操作、便签 ID、期望版本等上下文；不记录真实用户数据。

### 11.3 建议的 B2 工作包（待确认后写成正式计划）

3. 在 SQLite 层加入忙碌超时/重试与提交结果核验策略。
4. 增加故障注入测试矩阵。
5. 更新文档与 ADR（如涉及重试/隔离级别决策），执行独立审查。
