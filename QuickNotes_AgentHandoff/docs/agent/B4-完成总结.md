## 4. 关键行为

### 4.1 每日检查

```text
读取调度档目录
  -> 今日已有有效 Daily：AlreadyBackedUpToday（不写状态、不清理）
  -> 计算 SQL 指纹
  -> 状态指纹相同且基线日备份仍有效：NoChanges
  -> 调用 BackupCoordinator(Daily)
       -> 失败：Failed，不写状态、不清理；下一周期重试
       -> 成功：写备份前指纹状态（写失败只警告）→ 校验档目录 → 7+4 留存
```

- 状态只在成功日备份后写入；备份失败/今日已有/无变化不写。
- 指纹相同但状态对应日备份缺失/损坏 → 重新备份。
- 每次只按当前本地日期判断，不为停机期补造多天。
- `RunPeriodicAsync(interval)` 立即检查后循环；单实例 `SemaphoreSlim` 串行化；循环内非取消异常记录后继续，避免自动备份静默停摆。

### 4.2 留存

- 有效 Daily 按本地日期取最新；最近 7 个不同本地日期。
- 最近 4 个有有效日备份的不同 ISO 周（周一开始），每周取最新日备份；与日保留并集。
- 同文件兼作日/周只保留一次；同日旧包进入删除候选。
- 手动/无效/未知类型不进入删除；删除存储再次校验类型、目录边界与 `.zip` 扩展名。
- 仅在新日备份成功且通过 B3 校验后清理；新包受保护；无保留集不删除；删除失败只警告。
- 留存档重新校验 DB 条目大小/SHA-256；不解压 SQLite（创建时 B3 已完整校验）。

### 4.3 状态

`.quicknotes-backup-state.json`（原子写）：

```json
{
  "formatVersion": 1,
  "lastSuccessfulFingerprint": "schema=1;notes=5;...",
  "lastSuccessfulDailyAtUtc": "2026-10-28T09:30:00.0000000+00:00",
  "lastSuccessfulDailyLocalDate": "2026-10-28"
}
```

- 备份前指纹；备份期间新写入会让下次检查视为变化（安全）。
- 缺失/损坏/不可读 → 无基线；无今日日备份时备份。
- 备份目录不可用 → 检查失败、不写状态、不清理，下一周期重试。
- 状态文件不是备份包；留存忽略；B5 必须保留/忽略，不得当作数据库备份。

## 6. 审查与修复

- 标准轴 [严重]：留存存储原先只依赖策略排除手动备份 → 现在存储层再次校验 `BackupType.Daily`，手动包返回 `retention_unsafe_type` 并保留。
- 标准轴 [严重]：状态读取异常可能逃逸并停止周期循环 → 状态读取映射为 `Failed`；周期循环记录非取消异常后继续下一周期。
- 修复建议：基线检查同时使用状态本地日期；目录 IO 问题保留异常类型；服务记录目录 Issues 数量；指纹查询包在 deferred 读事务内；哈希流逻辑合并；移除不可达保留分支；补手动保护、ISO 年界、状态读失败、周期异常、端到端备份失败测试。
- 保留建议：`DailyBackupService.RunCheckAsync` 仍较长（步骤显式、已由测试覆盖）；`StateWarning` 仍是字符串；`SemaphoreSlim` 未实现 IDisposable（服务长生命周期）；崩溃遗留状态 `.tmp` 清理留 B6。

## 7. 已知限制

- SQL 指纹是启发式；未来标签/分类重命名/删除可能不改变计数/长度/MAX 时间，需要扩展指纹或改为 schema 变更计数器。
- 状态缺失/损坏会导致一次多余日备份；状态与备份目录同处。
- 调度频率由宿主决定；B4 只有服务，无 UI/后台宿主接线（B7）；推荐 15 分钟并在启动时立即检查。
- 调度档只做轻量校验；创建后静默损坏且大小不变的包可能被调度认为仍有今日备份；留存档哈希排除，B5 恢复必须重新完整校验。
- 真实磁盘满/权限/崩溃留 B6；单进程假设；备份包未加密；草稿/设置不在包内。

## 8. B5 准备

- 恢复前完整校验包/manifest/哈希/schema/结构/空间/草稿/写入任务；不信任“曾经校验过”。
- 恢复前创建保护快照；切换失败回退；回退失败停止写入并保留原库/保护文件。
- 保留未保存草稿；忽略/保留 `.quicknotes-backup-state.json`，不得当作数据库备份。
- 当前设备的备份目录、快捷键、开机启动等设置不被跨设备备份盲目覆盖。
