## 4. 关键行为

### 4.1 快照

- 源库以只读连接打开，使用 `SqliteConnection.BackupDatabase` 复制到独立临时 `.db`；不复制正在写入的主文件。
- 目标路径必须是新文件；目标或其 `-journal`/`-wal`/`-shm` 已存在时失败且不删除既有文件。
- 快照执行 `PRAGMA integrity_check`、`foreign_key_check`、`user_version`；`user_version < 1` 视为校验失败。
- 失败/取消删除本次创建的临时快照；源库保持可用；不启用 WAL，快照无 `-wal`/`-shm` 依赖。

### 4.2 备份包

```text
quicknotes-YYYYMMDD-HHmmss-fff-manual.zip
├─ manifest.json
└─ notes.db
```

manifest（格式版本 1，camelCase，枚举字符串）：

```json
{
  "formatVersion": 1,
  "backupType": "Manual",
  "createdAtUtc": "2026-10-28T09:30:00.0000000+00:00",
  "createdAtLocal": "2026-10-28T17:30:00.0000000+08:00",
  "schemaVersion": 1,
  "databaseFileName": "notes.db",
  "databaseSizeBytes": 123456,
  "databaseSha256": "64位小写十六进制"
}
```

- 包内固定两个条目；校验器拒绝额外/重复条目、绝对路径、`..`、反斜杠。
- 写临时 ZIP → 重新打开校验条目/manifest/哈希/大小 → 解压数据库复检完整性/外键/schema → 原子 `File.Move` 发布。
- 最终名冲突追加随机后缀，不覆盖已有包；发布前再次检查取消。
- 解压数据库默认限制 4 GiB（可配置），降低压缩炸弹耗盘风险。

### 4.3 失败语义

- 空目录/不支持的备份类型 → `ValidationFailed`；目录不存在/不可写 → `StorageUnavailable(DestinationUnavailable)`。
- 源库失败 → `SnapshotFailed(SourceUnavailable)`；BUSY/LOCKED 标记可重试。
- 快照校验失败 → `VerificationFailed(SnapshotVerificationFailed)`。
- 包写入失败 → `StorageUnavailable(PackageWriteFailed)`；包/ manifest 校验失败 → `VerificationFailed(PackageVerificationFailed)`。
- 取消抛 `OperationCanceledException`；临时目录/ZIP/解压文件尽力清理，清理失败记录 Warning（不改变主结果）。
- `BackupError.Diagnostics` 包含 backup ID、operation、稳定错误码与安全摘要；日志不记录便签内容或完整用户路径（包只记录文件名）。

## 7. 依赖与安全

- `QuickNotes.Infrastructure.Backup` 直接引用 `Microsoft.Data.Sqlite` 10.0.0 与 `SQLitePCLRaw.lib.e_sqlite3` 2.1.12（与 Sqlite 项目一致的漏洞覆盖策略）
- 未新增已知漏洞包；未引入 WAL、B4/B5 范围、UI 或 Rust FFI
- 备份包未加密；ZIP 内含完整数据库，需按用户备份目录权限保护
- 解压上限默认 4 GiB；B5 还需检查可用空间并重新执行完整预检

## 8. 已知限制与待决事项

- 在线备份 API 同步且无中途取消；取消只保证不发布半成品。
- 备份耗时随数据库增长；ZIP 压缩与解压校验增加 CPU/磁盘开销；B3 无进度 UI。
- 包只包含 SQLite 数据库；草稿、窗口布局、设备设置未进入包；B5 必须保留未保存草稿，B7 补齐设置策略。
- 真实磁盘满/权限/崩溃留 B6；B3 为可注入失败。
- WAL 未启用；读写并发仍可能遇到 BUSY，沿用 B2 的有界保存语义。
- 单进程/单实例假设；无跨进程备份锁。
- SQLite 仍是候选技术，未最终冻结。
