## 1. 结论与范围

C3 按 [C 阶段对接文档](Agent对接文档_C阶段.md) 完成：

- **schema v2**：便签颜色（跟随分类/手动）、字号覆盖、逻辑窗口布局；`app_settings`（全局字号、通知、全局隐藏、顶栏）；`database_meta`（数据库身份 + 变更序号）；设备设置独立 `device-settings.json`。
- **v1→v2 迁移**：启动时先在 `migration-protection/` 创建并验证原始 DB 保护快照，再事务化迁移；失败保留 v1，未来版本拒绝；状态更新为 schema 2，不重新首次引导。
- **确定性变更检测**：替换启发式 SQL 指纹为 `schema=2;db=<guid>;seq=<n>`；便签、分类、标签、关系、外观、设置写入与序号推进同事务；回滚不推进。
- **快照基线**：成功日备份只用包内快照 marker 写基线；快照期间新编辑不会被误判为已备份；失败/取消不推进。
- **恢复兼容**：v1 包先按原 manifest 哈希验证原始库，再迁移暂存库、轮换 identity，按目标哈希切换/核对；v2 包直接恢复同样轮换身份；缺失库重建支持 v1 包。
- **草稿 v2**：编辑器/草稿携带外观与布局字段，v1 草稿以默认外观读取；C2 编辑器行为保持。

前置条件：C2 已合并（`main` / `467ce93`）；C2 保存/草稿/恢复语义保持；C3 计划提交 `c49ce37`。

未实现：C4 备份/恢复 UI 与调度、C5 分类/标签/生命周期/托盘/快捷键/外观 UI、真实故障/性能/多屏验收（C6）。

## 5. 故障路径与数据保护

- 迁移：保护快照创建/校验失败则不迁移；迁移事务失败回滚并保留 v1；迁移后校验失败进入 NeedsRecovery，不把半迁移库当正常数据。
- 恢复：当前库取消/失败不切换；v1 包原哈希失败拒绝；迁移失败清理暂存、当前库不变；切换/回退失败保持 B5 阻断语义；目标哈希核对防止“迁移库比原包哈希”的错误。
- 变更序号：写入失败/回滚不推进；marker 缺失时备份失败或基线不推进，不静默跳过。
- 设备设置：仅本机文件，恢复不读写；未知版本不覆盖。
- 草稿：v1 草稿默认外观读取；损坏/未知版本保留证据；恢复不自动提交。

## 7. 已知限制与 C4 入口

- C3 没有颜色/字号/布局 UI、设置页、备份/恢复 UI；这些字段目前只有数据层与编辑器 API（C5）。
- 迁移保护快照只保留原始 DB，C3 无自动恢复/清理 UI；C4 提供入口与策略。
- 分类/标签写操作无并发版本列（单管理窗口假设）；C5 若引入并发编辑需评估。
- `device-settings.json` 已有存储层，但尚未接入宿主/设置页；C4 备份目录、C5 开机启动/快捷键/显示器绑定使用。
- 快照/基线身份失效依赖恢复/迁移真实执行；真实强杀/断电下的迁移中断、卷满/ACL、多屏/DPI、性能/长时间未验证（C6）。
- **C4 入口：** 使用 `IApplicationSettingsRepository`/`IDeviceSettingsStore`、迁移保护目录、v1/v2 恢复路径与快照 marker；实现备份目录选择、调度、恢复 UI、旧会话失效。
