## 4. 覆盖亮点

- **保存状态**：仅 `SaveResult.Saved` 且快照序号匹配时显示已保存；保存中继续输入后，完成结果不把新内容标为已保存。
- **串行保存**：每个 `NoteEditorSession` 使用保存门；后续保存等待前一次完成并使用最新快照。
- **多便签独立**：不同便签的会话并行保存互不阻塞，真实 SQLite 下各自落到对应 NoteId。
- **未知结果**：`OutcomeUnknown` 不自动重试；用户触发 `RetryAsync` 回读真实数据库：内容/标签/版本匹配则确认 Saved，不匹配转 Conflict，新建便签不存在则用稳定 ID 重试创建。
- **冲突**：保留本地快照与草稿，提供重载数据库版本与另存为新便签；无自动合并。重载时若旧草稿删除失败，保留诊断状态而非静默忽略。
- **草稿保护**：草稿去抖 300ms、最长 2s；草稿失败显示未保护并保留编辑内容；数据库保存成功只清理匹配草稿。
- **重启恢复**：已落盘草稿可在重启后列出、查看、恢复（不自动提交）或显式丢弃；损坏草稿记录问题但不删除、不阻断启动。
- **关闭/切换**：关闭或切换便签前先落草稿再保存；失败/未知时提示保留草稿退出，不静默丢弃。
