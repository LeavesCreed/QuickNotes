# Agent 对接文档：C 阶段桌面应用集成与可恢复性验证

**版本：** 1.0  
**日期：** 2026-10-28  
**阶段：** C — 桌面宿主、编辑交互、设置与恢复闭环  
**平台目标：** Windows 11 x64  
**目标原则：** 数据正确性与可恢复性优先；分工作包交付、逐包验收  
**首轮执行范围：** C0 + C1；后续工作包按依赖顺序单独推进

## 1. 当前项目状态与阶段目标

### 1.1 已有基础

- 产品基线为仓库内 `docs/product/PRD_v1.0.md`，实施前以实际文件为准。
- A 阶段窗口/托盘原型已有基本用户验证；DPI、断屏、单实例和异常路径仍需明确测试证据。
- B1–B6 已实现数据模型、SQLite 持久化、保存协调、文件草稿、一致性备份、自动留存、整库恢复与故障注入测试。
- B7 完成交付文档与回归报告。报告记录 Windows 11 x64 下构建 0 警告、0 错误，245/245 测试通过，0 失败、0 跳过。
- B7 文档中的分支为 `feature/b7-delivery`，基于 `main` / `68c5a9d`，撰写时待手动合并。当前仓库状态必须由 C0 重新确认，不得据此推断已经合并。
- B 阶段解决方案为 `QuickNotes_AgentHandoff/QuickNotes.DataPrototype.sln`，数据层未依赖 WPF，尚无与 B 数据层集成的完整桌面应用入口。

以上为上传资料中的历史证据，本文件未检查用户当前本地仓库、PRD 全文或 A 阶段源码；不得把这些历史结果写成 C 阶段已经执行的验证。

### 1.2 需要承接的缺口

- 编辑器尚未接入保存、草稿捕获、草稿恢复及错误提示。
- 尚无正式宿主、单实例协调、应用数据目录、启动恢复检查和自动备份宿主接线。
- 当前 schema v1 未包含便签外观、窗口布局、全局隐藏恢复状态、应用设置和设备配置；当前备份只是数据层快照。
- 当前恢复要求现有数据库存在；首次运行、当前库缺失和崩溃遗留 staging 的处理尚未实现。
- 当前变更指纹为启发式，存在分类/标签同长度重命名等漏检风险。
- 回退失败后会阻断写入，但缺少可供用户操作的诊断、恢复和重新开放写入入口。
- 真实空间耗尽、系统 ACL、强杀进程、性能与长时间运行尚缺验收证据。

### 1.3 C 阶段目标

把 A 阶段桌面能力与 B 阶段数据服务接起来，交付一个可以持续试用的 Windows 11 应用，完成以下闭环：

> 启动 → 创建/编辑 → 保存与草稿保护 → 退出/异常中断 → 重开找回 → 备份 → 预检与确认恢复 → 继续编辑。

C 阶段继续使用现有 `.NET 10 + WPF + SQLite` 作为集成验证基线；最终选型以 C 阶段验收和 ADR 为依据。沿用单实例、非 WAL 的已验证边界，避免同时改动多个核心机制。

### 1.4 范围与决策规则

- 本文是基于 B 阶段成果提出的 C 阶段执行契约，不替代已确认 PRD。C0 必须建立“PRD 条款—工作包—验收证据”映射。
- 正常的实现细节可在既有授权内选择合理方案并记录 ADR；无需为每个接口、目录或类名反复请求确认。
- 如发现与 PRD 冲突、需要改变已确认产品规则或扩展产品范围，应先说明具体冲突；可独立推进的工作继续执行。
- C 阶段包含基础诊断日志和可运行试用交付；正式导出、安装器、自动更新、备份加密、云同步、增量备份和 Rust FFI 留到后续阶段，除非实际 PRD 或已有授权另有要求。
- 不把 WAL 或多实例支持夹带进 UI 集成。未来如需引入，单独评估备份、恢复、锁和兼容性协议。

## 2. 必须回答的技术问题与不变量

### 2.1 必须回答的问题

1. 如何复用 A 阶段窗口/托盘与 B 阶段类库，避免 UI 直接操作 SQLite 或绕过保存协调器？
2. 如何在打开数据库前保证单实例，并区分首次安装与原有数据库意外丢失？
3. 退出、崩溃、恢复中断后，如何确定当前库、保护快照、回退副本和草稿的可用性？
4. 如何保证连续编辑、在途保存和迟到回调不会让旧内容覆盖新内容或误显示“已保存”？
5. 草稿如何自动捕获、落盘、提示和恢复，草稿存储本身失败时如何提示？
6. schema v2 如何表达完整产品状态，同时保留设备配置边界和 v1 数据/备份的升级路径？
7. 如何可靠检测所有应备份数据的变化，并让成功基线对应备份包中的实际快照？
8. 恢复成功后如何刷新窗口、使旧编辑会话失效，并避免草稿自动覆盖恢复后的数据？
9. 如何在 UI 中呈现保存、备份、恢复、回退失败和写入阻断的真实状态？
10. 如何用 Windows 真实故障环境、自动化回归和人工检查证明应用可持续试用？

### 2.2 不可退化的规则

- 只有数据库提交成功，或提交异常后回读确认一致，才允许报告保存成功。
- 新编辑尚未提交时，旧保存完成不得把当前编辑器标为“已保存”。
- 版本冲突、保存失败和提交结果未知不得静默覆盖任一方内容。
- 草稿保存成功与数据库提交成功分别呈现；草稿落盘不等于正式保存。
- 数据库写入、迁移、恢复必须受统一协调；恢复失败后的写入阻断不得被重启或重建服务对象绕过。
- 新备份通过校验后才清理超额自动备份；保留 7 份日备份 + 4 份周备份；同一物理文件兼任日/周时按并集处理。
- 手动备份默认不参与自动清理；失败不算当日成功；当天无变化时不生成不必要的重复日备份。
- 日历、ISO 周、周代表和同日处理沿用 B4 已接受 ADR；如需改变，必须先对照 PRD，不能把检查周期当作备份频率。
- 恢复前重新完整校验，切换前保护当前可用数据；失败回退，回退失败保留证据并停止写入。
- 设备备份目录、开机启动状态和显示器标识不得被导入备份盲目覆盖。
- 所有测试使用合成数据和隔离目录/隔离卷；不访问真实用户便签或清理真实备份。

### C0 — 仓库和环境检查、集成设计

**工作：**

- 阅读根目录 `AGENTS.md`、`agent.md`、PRD、A 阶段交付、B 阶段对接文档、B7 总结/测试报告/限制和相关 ADR；文件缺失应列明。
- 检查分支、工作区、未提交修改与 B7 合并状态；保留用户改动，不擅自合并历史分支或整理无关文件。
- 检查 Windows 11 x64、SDK、WPF 构建条件、SQLite 原生依赖、解决方案与项目引用。先记录 `dotnet --info`。
- 按现有 README 构建并运行 B 阶段回归；245 是历史基线，实际结果单独记录。
- 检查 A 阶段可复用入口、窗口/托盘代码、线程模型和退出行为，确认 A 与 B 的组合位置。
- 建立 PRD 覆盖表，标记已实现、待集成、待新增、待核实和明确延期项；特别核对 PRD 11.5、11.8 及窗口、关闭、隐藏、快捷键等规则。
- 确定宿主组合根、数据/草稿/备份/日志目录和测试隔离方案，形成 C 阶段设计说明与 ADR 清单。
- 定义性能验收使用的数据量、设备条件和指标；具体阈值以 PRD 或记录的候选预算为准，不能测试完成后临时定义“通过”。

**验收：**

- 当前环境、历史证据和本次实测清楚区分；通过/失败/未运行分别记录。
- B7 合并状态、A/B 代码连接方案和目标解决方案明确。
- PRD 映射可追溯；发现的冲突和缺失有明确处理路径。
- 没有覆盖用户修改、迁移真实数据库或新增无关依赖。

**交付：** C0 环境与基线报告、集成设计、实施计划、风险清单。

### C1 — 桌面宿主、单实例与启动安全

**工作：**

- 建立/复用 WPF 宿主，在组合根连接 Application 与基础设施；保持 Domain/Application 不依赖 WPF。
- 在打开数据库、草稿存储和启动后台任务之前取得同一用户/数据目录范围的实例所有权。第二实例激活既有实例或明确退出，不接触数据写入。
- 建立正式数据目录、初始化标记和最小诊断日志；日志记录操作、错误码和关联 ID，不记录便签正文或草稿内容。
- 区分“确属首次运行”和“已初始化但当前库缺失”。缺失/损坏/不兼容不能自动创建空库并继续写入。
- 实现启动检查结果：正常启动、首次初始化、需要恢复处理、只读诊断/写入阻断。
- 扫描应用自身已知的恢复/备份临时产物、保护快照和回退文件；先验证归属、引用关系、当前数据库及恢复状态，再决定保留或清理。
- 不能仅凭目录名称、时间戳、schema 或行数选择恢复来源。无法证明一致时保留文件，进入安全入口。
- 遵循 SQLite 热 journal 恢复流程，沿用当前 WAL 拒绝策略；不得直接删除数据库 sidecar 以绕过检查。
- 补齐恢复关键阶段的持久化状态与启动识别；若状态不完整/损坏且存在切换歧义，进入阻断而非猜测成功。
- 为回退失败提供可操作入口：查看诊断、选择已验证恢复来源、重新校验和重试。重新开放写入前必须确认当前库有效且中断已处理；不能靠重启自动清除阻断。
- 支持当前库确实缺失时从已验证备份安全重建：同卷暂存、完整校验、发布与失败保留。存在但损坏的原库先保全；无当前库时记录“无当前库可做保护快照”，不得伪造保护成功。
- C1 可提供最小启动/诊断窗口，以承载错误和恢复入口；本包不展开编辑器及完整设置界面。

**验收：**

- 合成数据环境中首次启动、正常重开、第二实例启动分别符合预期。
- 首次初始化失败不留下被误认为已完成的状态，重试路径明确。
- 已初始化但当前库缺失时进入恢复流程，不静默初始化空库。
- 有价值的回退副本、保护快照和未完成恢复目录不被启动清理删除；重复执行检查不会破坏恢复机会。
- 不兼容库、当前库损坏、恢复状态损坏、WAL sidecar 和回退失败均有安全结果。
- 当前库缺失恢复失败不报告成功；成功重建后完整性与外键检查通过。
- 中断后的阻断状态跨进程重启仍有效，完成验证或安全恢复后才能解除。

**测试：** 启动协调单元测试、临时目录/真实 SQLite 集成测试、同用户第二进程测试及 Windows 最小启动人工检查。真实强杀矩阵在 C6 补充。

**交付：** 可启动宿主、启动/恢复状态机、单实例和目录策略 ADR、C1 测试报告与完成总结。

### C2 — 最小编辑、保存状态与草稿保护

**工作：**

- 通过 Application 接口实现新建、打开、编辑和再次打开便签；正文/标题及已有基础字段先使用当前模型。
- 保存统一经过既有 `INoteSaveCoordinator`；核实真实接口，禁止 WPF 直接执行 SQL 或捕获异常后假报成功。
- 实现自动保存的触发、去抖、取消和按便签串行协调；优先对照 PRD，无约定的时序写 ADR。
- 为编辑快照提供稳定身份/序号；在途保存完成后只有与当前快照一致，才能显示“已保存”。迟到结果不得覆盖新文字或新草稿。
- 接入 `INoteDraftStore` 自动捕获与持久化；不能只在保存失败后才尝试保护。草稿也失败时明确显示“内容尚未得到本地保护”，保留编辑内容和重试入口。
- 覆盖新便签尚未创建成功的草稿；创建/重试使用稳定身份，避免同一编辑操作产生重复便签。
- 明确编辑状态：已修改、保存中、已保存、保存失败、版本冲突、结果未知，以及草稿保护状态；状态由实际结果驱动。
- 草稿恢复展示来源和时间，提供查看、恢复和显式丢弃；损坏草稿保留可诊断证据，不作为启动失败的唯一原因。
- 冲突时保留数据库版本与本地版本，提供比较、另存或重新载入等符合 PRD 的处理路径；不做静默自动合并。
- 明确窗口关闭、应用退出和系统结束会话的在途保存/草稿处理。UI 保持响应，不能把驱动可能持续数秒的重试放在 UI 线程。
- 沿用 B2 的真实保存语义：BUSY/LOCKED 最多 3 次尝试，历史最坏约 3.2–3.4 秒；不擅自重新承诺 950ms。

**验收：**

- 完成“启动→新建→编辑→保存→退出→重开”的最小使用闭环。
- 连续快速输入、保存途中继续输入、延迟回调和多便签独立编辑不丢更新、不误显示最新内容已保存。
- 保存失败、冲突、提交未知、草稿读写失败均有明确提示；草稿不因无关/旧保存成功而被删除。
- 已成功落盘的草稿可在重启后找回；未落盘的最后编辑窗口如有边界，应如实说明，不能宣称任意时刻强杀都零损失。
- 未创建成功的新便签可从草稿继续，重试不产生重复便签。
- 退出期间失败有保留内容和恢复路径，UI 不长时间冻结。

**交付：** 最小编辑器、保存/草稿状态与交互说明、时序 ADR、自动化测试和人工操作清单。

### C3 — schema v2、设置边界与可靠变更检测

**工作：**

- 按 PRD 11.5 补齐便签颜色、字号、默认/覆盖关系、窗口位置/尺寸、显示意图、全局隐藏恢复、应用设置和顶栏配置；先梳理已有字段，避免重复建模。
- 建立字段策略表：字段归属、版本/并发策略、是否进入备份、恢复行为、跨设备映射与默认值。
- 区分可迁移应用状态与当前设备配置。备份目录、显示器标识、开机启动注册和快捷键实际注册状态具有本机语义；是否携带及如何恢复必须由 PRD/ADR 明确，默认不盲目覆盖本机状态。
- 设备配置采用独立版本与原子保存。窗口几何使用可映射的逻辑值，实际显示器标识与坐标修正由宿主处理。
- 实现 v1→v2 迁移：迁移前生成并验证保护快照，在独立准备区或事务中完成，校验后启用；失败保持原库可用，未知未来版本拒绝降级。
- 扩展快照/manifest/schema 校验与恢复兼容矩阵。原有 v1 备份必须可进入“先验证原始库，再迁移暂存库”的恢复路径。
- 迁移会改变数据库字节：先以原 manifest 哈希验证包内原始库，再校验迁移后的目标库并记录目标校验值；切换后按目标校验值核对，不拿迁移后的库直接比原包哈希。
- 数据库 schema 版本与备份包格式版本分别管理；若 ZIP 仍保持原结构，不因为 schema 升级而无理由改变包格式。任何变化均写兼容性 ADR。
- 替换启发式 SQL 指纹，采用持久化变更序号/等效确定性机制；所有应备份内容的写入与变更标记在同一事务提交，包括分类/标签重命名、关系、外观和应用设置。
- 变更标记应识别数据库身份/恢复世代，避免恢复后相同序号被误判为相同数据；迁移/恢复后正确失效或重建调度基线。
- 成功备份基线必须对应包内实际快照的标记，不得在快照生成后读取更新的源库标记并把未包含的新编辑当作已备份。失败/发布前取消不推进成功基线。
- 对旧状态文件、未知状态版本和丢失基线采取保守兼容策略，沿用日备份规则而非增加无约定的同日备份。

**验收：**

- 字段策略表覆盖实际 PRD 所需状态；重开数据库后值与关系一致。
- v1→v2 成功、迁移失败、重复启动、取消/中断、未来版本拒绝均有测试。
- v1 备份恢复到 v2 应用可验证、可迁移；任何失败不破坏原有数据与保护副本。
- 同长度分类/标签重命名、颜色修改、关联变化等不再漏检；在符合日备份条件时会被识别为未备份变化。
- 事务回滚不增加成功变化标记；快照期间新增编辑仍保留为待备份变化。
- 旧调度状态、恢复后序号碰撞与新备份目录切换不会造成错误的“已备份”结论。
- 本机专属状态不被跨设备恢复盲目替换，便签布局有安全回退。

**交付：** schema v2 与迁移实现、字段策略表、兼容矩阵、变更检测 ADR、模型/备份文档和测试。

### C4 — 备份 UI、自动调度与恢复交互

**工作：**

- 提供备份目录选择、可用性检查、最近成功时间、最近失败/警告和重试入口；目录切换不删除或搬移旧备份，除非用户另有明确操作。
- 接入手动备份、备份列表与校验状态。应用内手动删除备份须用户显式操作并确认目标，不与自动留存混用。
- 宿主启动后立即检查，随后定期检查；建议沿用 B4 的 15 分钟候选值并写 ADR。系统唤醒后补检查，任务不重入，失败后后续周期仍可重试。
- 正式启用自动备份前，C3 的确定性变更检测及快照基线测试必须通过。
- 恢复确认展示可验证的备份时间、可用来源信息、schema/格式版本、便签等数量、整库替换范围与设备设置策略。缺失信息明确标未知，不凭文件名编造来源。
- 恢复前冻结新的编辑提交、处理在途保存并捕获当前草稿；草稿落盘失败时不静默继续覆盖。调用共享写入门，等待在途写入完成。
- 复用并扩展 B5 的完整预检、保护快照、暂存、切换、验证和回退；C1 的缺失库恢复和 C3 的迁移路径采用同一安全边界。
- 进度按真实阶段展示，区分可取消与不可取消阶段。同步快照 API 不能立即取消时如实显示；发布成功后不能因随后取消谎报失败。
- 恢复成功后使旧编辑会话、预期版本和异步回调失效，重建/刷新服务与窗口；即使旧新库的便签 ID 和版本相同，也不能接收恢复前的迟到保存。
- 恢复保留的草稿标记为恢复前来源，提供比较或另存；不得自动提交到恢复后的同 ID 便签。
- 回退成功应明确显示恢复失败且已回退；回退失败保持写入阻断，并提供 C1 的诊断/恢复入口和保护文件位置。
- 可迁移设置、窗口状态及便签数据按策略恢复，设备专属注册状态经本机重新验证；恢复完成后调度基线正确更新/失效。

**验收：**

- 用户可通过 UI 完成手动备份、查看结果、选择备份、预检确认和整库恢复。
- 7 日 + 4 周规则、手动排除、当天无变化、目录不可用、失败后重试均有宿主级证据。
- 包损坏、空间不足、版本不兼容、草稿保存失败和用户取消不会破坏当前库；没有失败路径报成功。
- 恢复中 UI 保持响应，不允许新的普通写入越过恢复门。
- 切换失败/回退失败按真实结果呈现，重启后仍遵循 C1 的恢复检查。
- 恢复后的窗口、正文、分类/标签与应恢复设置一致；旧会话不能把恢复前内容写回。

**交付：** 备份/恢复界面、调度接线、恢复交互说明、端到端测试及错误 UX 清单。

### C5 — 分类/标签、生命周期与桌面行为完善

**工作：**

- 按 PRD 接入分类、标签、归档、回收站与恢复等管理操作。隐藏、关闭窗口、归档和删除按产品定义分别处理。
- 管理操作使用 Application 服务、事务、版本保护及统一写入协调；不得为了 UI 便利绕过 C3 变更记录。
- 复用 A 阶段托盘和窗口能力，完善新建、打开、显示/隐藏、置顶、全局隐藏恢复、退出和快捷键。
- 保存并恢复便签外观、窗口几何和顶栏配置；默认值与便签覆盖的关系一致。
- 处理快捷键冲突、注册失败和配置回退；开机启动如属 PRD 范围，仅按用户明确设置注册，并核验实际状态。
- 处理多显示器、不同 DPI、工作区变化、显示器断开和跨设备布局；确保便签可找回且仍可操作。
- 全局隐藏恢复与归档/回收站可见性保持一致，不把非 Active 便签错误显示为活动窗口。
- 错误提示提供可执行操作，日志和诊断避免泄露正文；补充键盘操作、焦点和基本可访问性。

**验收：**

- 分类/标签修改、生命周期切换、重开应用和备份恢复后关系一致。
- 托盘、快捷键、显示/隐藏、置顶和关闭/退出行为符合 PRD，并有操作证据。
- 快捷键冲突和开机启动注册失败可诊断，配置不伪装成功。
- 在已列明的 DPI/多屏/断屏测试矩阵中，便签能够回到可操作工作区。
- A 阶段历史“基本验证”不代替本包回归；未测设备组合单独标记。

**交付：** 管理界面与桌面行为、设备适配说明、自动化测试和人工矩阵。

### C6 — 真实故障环境、性能与稳定性

**工作：**

- 在隔离测试目录、测试账户或可销毁卷中执行真实故障；不得耗尽系统卷、修改真实用户 ACL 或强杀用户正在使用的应用。
- 至少覆盖保存/草稿/备份/迁移/恢复时的空间不足与权限拒绝、备份目录临时离线、应用进程强杀和后续启动。
- 在可控故障宿主中设置阶段检查点，再由外部进程终止；覆盖备份发布前后、迁移关键阶段、恢复切换前后和回退阶段，避免只用随机时序声称覆盖。
- 特别验证跨重启写入阻断、当前库缺失、安全清理、草稿恢复、旧会话失效和保护文件保留。
- 验证恢复中的第二实例启动不会形成竞争写入；单实例 IPC/激活失败有明确结果。
- 全量回归、关键套件重复执行、长时间编辑/空闲、休眠唤醒和较大数据量性能按预先记录的次数、时长和预算执行。
- 性能至少记录启动、输入响应、保存、备份、恢复、内存/句柄/磁盘增长；区分 UI 响应与后台完成耗时。
- 强杀进程不等于真实断电；虚拟卷故障不等于所有硬件故障。未执行的项目保留为未运行，不推广为已覆盖。

**验收：**

- 每个故障用例记录环境、故障位置、预期、实际结果、重启结果与证据。
- 已确认保存的数据在相应测试场景中可找回；可用草稿有明确恢复入口；不把“没有抛异常”作为完整性通过标准。
- 所有关键失败路径没有误报成功、静默空库、意外清理保护文件或绕过写入阻断。
- 性能/稳定性依据预先记录预算判定；问题修复后执行相关回归，最终结果可复现。
- 测试清理只处理自身产物，并撤销测试注册的快捷键/开机启动等副作用。

**交付：** 自动化故障宿主/脚本、真实环境测试报告、性能/稳定性报告和剩余风险。

## 5. 接口边界与必需技术决策

### 5.1 复用优先

先检查并复用实际的保存协调器、草稿存储、备份协调器、日备份服务、恢复协调器和共享写入门。以下是职责边界，名称可按现有代码调整，不要求再造同名抽象。

| 边界 | 职责 | 约束 |
| --- | --- | --- |
| Desktop 组合根 | 服务生命周期、窗口、后台任务接线 | 不承载 SQL/包校验/迁移算法 |
| 单实例协调 | 实例所有权、第二次启动激活 | 取得所有权前不打开数据写入资源 |
| 启动恢复协调 | 初始化判定、遗留状态识别、安全入口 | 不能把重启当作解除阻断的依据 |
| 编辑会话协调 | 编辑快照、串行保存、迟到结果过滤 | 恢复后整个旧会话失效 |
| 既有保存与草稿服务 | 提交语义、冲突、草稿读写 | UI 不绕过；草稿状态与提交状态区分 |
| 设置与布局服务 | 应用/设备策略、原子持久化、映射 | 明确是否参与备份与变更检测 |
| schema 迁移服务 | 保护、版本判断、迁移、校验、失败保留 | 不原地半升级后继续写入 |
| 变更检测/快照标记 | 确定性变化识别、实际快照基线 | 所有相关写入与标记同事务 |
| 备份与调度服务 | 创建、校验、目录、留存和周期检查 | 非重入；失败后可继续；保留既有规则 |
| 恢复协调与写入门 | 冻结、预检、保护、切换、回退、阻断 | 写入入口统一受控；跨重启可诊断 |

仅在需要隔离平台行为或支持有价值测试时新增接口，不为每个类引入包装层。基础设施中的测试注入钩子不得变成业务扩展入口。

### 5.2 ADR 最小清单

1. A/B 集成、WPF 宿主组合根、线程和服务生命周期。
2. 单实例范围、激活机制、数据目录、首次运行与缺失库区分。
3. 启动恢复状态、跨重启写入阻断、安全清理与恢复来源判定。
4. 编辑快照、保存触发、草稿捕获/退出策略、冲突与未知结果 UX。
5. schema v2、字段/设备策略、升级保护、v1 备份恢复和版本兼容矩阵。
6. 确定性变更标记、快照基线、恢复世代和旧状态文件兼容。
7. 调度周期、失败重试、唤醒行为、恢复后的服务/编辑会话失效。
8. 多屏/DPI 布局映射、快捷键/开机启动实际状态与配置一致性。
9. 故障宿主、真实故障边界、性能预算与技术选型评审。

已有 ADR 能覆盖的内容只补充交叉引用；新的决定不改写历史已接受事实。

4. 实际构建/测试命令、环境和通过/失败/未运行结果。
5. 故障路径、数据保护与恢复验证结果。
6. ADR、兼容性变化、审查发现与修复。
7. 已知限制、未解决问题和下一工作包的进入条件。
8. 当前分支、工作区与提交状态；不把待合并写成已合并。

## 7. 阶段完成标准

- [ ] C0 完成仓库、环境、B7 状态和历史基线核对，PRD 映射可查。
- [ ] 单实例先于数据资源打开；首次运行、缺失库、损坏库和未知版本有不同且安全的路径。
- [ ] 启动恢复能识别中断状态，保护/回退文件不被误删；写入阻断跨重启有效。
- [ ] 最小编辑与保存闭环可运行；快速编辑、保存失败、冲突和结果未知不误报成功。
- [ ] 草稿自动捕获、落盘、恢复和失败提示可验证；未落盘内容的边界有说明。
- [ ] schema v2 和设置策略覆盖 PRD 所需状态，升级有保护、失败有回退。
- [ ] v1 数据/备份兼容路径、未来版本拒绝和迁移后校验有测试。
- [ ] 确定性变更检测覆盖相关写入；备份成功基线对应包内快照，恢复不复用错误基线。
- [ ] 备份/恢复 UI 与调度可运行，7 日 + 4 周及手动保护规则保持一致。
- [ ] 恢复成功后旧编辑会话失效；保留草稿不会自动覆盖恢复后的数据。
- [ ] 分类/标签、生命周期、托盘/快捷键和窗口状态符合 PRD；DPI/多屏实测范围明确。
- [ ] 真实故障、稳定性和性能按预定矩阵执行，失败与未运行如实披露。
- [ ] 可运行试用构建、README、格式/兼容文档、ADR、测试报告和已知限制齐全。
- [ ] 技术选型评审结论有证据，阻断问题未解决时不标整体通过。

C 阶段完成后，再依据实际 PRD 覆盖和剩余风险安排导出、安装/升级、正式发布等后续工作；不提前把未实现或未验证的能力计入交付。
