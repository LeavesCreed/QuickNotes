# B7 数据模型与备份格式

**日期：** 2026-10-28\
**范围：** B 阶段数据原型（schema v1、草稿、备份包、留存状态、恢复协议）\
**代码基线：** `main` / `68c5a9d`（B6 已合并）

本文描述**当前实现**，不是完整产品数据模型。PRD 11.5 中的便签颜色/字号、窗口位置/尺寸、隐藏恢复状态、应用设置与设备专属配置尚未进入 B 阶段 schema 或备份包，见 [已知限制](B7-已知限制与后续建议.md)。

## 1. SQLite 数据模型（schema v1）

数据库使用 SQLite rollback journal 模式，不启用 WAL；`PRAGMA user_version=1`。初始化只接受版本 0 并创建 schema；版本 1 直接返回；大于 1 或其它值拒绝启动。

### 1.1 表结构

```sql
CREATE TABLE categories (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL COLLATE NOCASE UNIQUE,
    default_color TEXT NOT NULL,
    is_system INTEGER NOT NULL CHECK (is_system IN (0, 1))
);

CREATE TABLE tags (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL COLLATE NOCASE UNIQUE
);

CREATE TABLE notes (
    id TEXT PRIMARY KEY,
    title TEXT NULL,
    body TEXT NOT NULL,
    created_at_utc TEXT NOT NULL,
    modified_at_utc TEXT NOT NULL,
    version INTEGER NOT NULL CHECK (version >= 1),
    lifecycle INTEGER NOT NULL CHECK (lifecycle IN (0, 1, 2)),
    category_id TEXT NOT NULL,
    is_pinned INTEGER NOT NULL CHECK (is_pinned IN (0, 1)),
    display_intent INTEGER NOT NULL CHECK (display_intent IN (0, 1)),
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE RESTRICT,
    CHECK (lifecycle = 0 OR display_intent = 0)
);

CREATE TABLE note_tags (
    note_id TEXT NOT NULL,
    tag_id TEXT NOT NULL,
    PRIMARY KEY (note_id, tag_id),
    FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);

CREATE INDEX ix_notes_category_id ON notes(category_id);
CREATE INDEX ix_notes_modified_at_utc ON notes(modified_at_utc DESC);
CREATE INDEX ix_note_tags_tag_id ON note_tags(tag_id);
```

初始化时插入唯一系统分类：

```text
id           6f2a98f2-20de-4f4e-a2f4-8a570c4625d7
name         未分类
default_color #E6E6FA
is_system    1
```

### 1.2 编码约定

| 逻辑类型 | 存储 | 说明 |
|---|---|---|
| GUID | `TEXT` | `Guid.ToString("D")`（小写带连字符） |
| 时间 | `TEXT` | `DateTimeOffset.ToUniversalTime().ToString("O")`，ISO 8601 往返格式，UTC |
| 布尔 | `INTEGER` | 0/1 |
| 枚举 | `INTEGER` | 见下表 |
| 正文/标题 | `TEXT` | 标题可空；正文非空 |

| 枚举 | 值 |
|---|---|
| `NoteLifecycle` | `Active=0`、`Archived=1`、`Trash=2` |
| `NoteDisplayIntent` | `Hidden=0`、`Visible=1` |
| `BackupType` | `Manual=0`、`Automatic=1`、`Daily=2`、`Weekly=3` |

`CHECK (lifecycle = 0 OR display_intent = 0)` 表示只有正常便签可以为 Visible；归档/回收站必须 Hidden。

### 1.3 关系与完整性

- `notes.category_id` → `categories.id`，`ON DELETE RESTRICT`：有便签的分类不能删除。
- `note_tags.note_id` → `notes.id`、`note_tags.tag_id` → `tags.id`，均 `ON DELETE CASCADE`：删除便签或标签自动删除关联。
- `note_tags` 主键 `(note_id, tag_id)`：同一标签不能重复关联同一便签。
- 分类名/标签名使用 `COLLATE NOCASE UNIQUE`：大小写不同的同名值视为冲突。
- 每次连接打开执行 `PRAGMA foreign_keys=ON`，并由测试验证外键、`integrity_check` 与 `foreign_key_check`。

### 1.4 并发与版本

- 创建便签写入 `version=1`。
- 更新与状态变更必须提供 `expectedVersion`，SQL 只更新 `id = ? AND version = ?` 的行；成功后版本 `+1`。
- 版本不匹配返回冲突路径；不存在的便签返回未找到；提交结果未知时由保存协调器回读核验，避免把未提交报告为成功。
- 保存事务使用 deferred `BEGIN`，BUSY/LOCKED 最多 3 次应用层尝试；提交阶段不重跑整次保存。

### 1.5 当前未建模的 PRD 字段

PRD 11.5 的完整备份要求包含颜色、字号、显示/隐藏、置顶、位置/尺寸、全局隐藏恢复状态、应用设置和顶栏配置。B 阶段 schema 只建模：

```text
便签：ID、标题、正文、创建/修改时间、版本、生命周期、主分类、置顶、显示意图
分类：ID、名称、默认颜色、是否系统
标签：ID、名称
关联：便签-标签
```

便签级颜色/字号/窗口位置/尺寸、全局隐藏恢复状态、应用设置与设备专属配置（备份目录、开机启动、显示器标识）**不在当前 schema 或备份包内**。

## 2. 草稿格式

草稿用于保存协调失败时保留未提交内容，不进入备份包。

- 目录：由宿主提供；文件名 `<draftId:D>.json`。
- 写入：临时文件 + `File.Move(overwrite: true)`；进程内 `SemaphoreSlim` 串行化；`Flush(flushToDisk: true)` 后切换。
- 读取：按文件名解析 `draftId`；JSON 损坏、字段非法、版本不支持分别产生 `draft_corrupt` / `draft_unsupported_version` / `draft_io` 错误。
- 恢复：预检统计草稿；存在草稿且未显式允许时阻止恢复；允许后恢复仍保留草稿目录。

示例：

```json
{
  "formatVersion": 1,
  "draftId": "5a0f8c2e-6f4e-4f0e-9f6e-2c9a7b1d3e44",
  "noteId": "9d1c7e4a-2b3f-4c5d-8e6f-7a8b9c0d1e2f",
  "baseVersion": 3,
  "title": "未保存标题",
  "body": "未保存正文",
  "categoryId": "6f2a98f2-20de-4f4e-a2f4-8a570c4625d7",
  "tagIds": ["1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d"],
  "isPinned": false,
  "displayIntent": "Visible",
  "capturedAtUtc": "2026-10-28T09:30:00+00:00"
}
```

## 3. 备份包格式

### 3.1 文件命名与类型

```text
quicknotes-yyyyMMdd-HHmmss-fff-<type>.zip
quicknotes-yyyyMMdd-HHmmss-fff-<type>-<4hex>.zip   # 同一毫秒命名冲突时
```

- 时间使用 UTC；`<type>` 为小写 `manual` 或 `daily`；同毫秒冲突追加 4 位小写十六进制随机后缀。
- `BackupCoordinator` 只接受 `Manual` 与 `Daily`；`Automatic`/`Weekly` 是保留枚举，当前不生成。
- 包位于调用方提供的备份目录；B3 不创建/修改该目录。

### 3.2 ZIP 条目

```text
quicknotes-20261028-093000-000-daily.zip
├─ manifest.json
└─ notes.db
```

- 只允许恰好两个条目，名称必须精确为 `manifest.json` 与 `notes.db`。
- 条目数不是 2、名称不符、重复条目均拒绝；因此绝对路径、`..`、目录条目和其它额外文件不会被接受。
- ZIP 不加密；`notes.db` 是完整 SQLite 数据库字节（rollback journal 模式，不包含 `-wal`/`-shm`）。

### 3.3 manifest.json

```json
{
  "formatVersion": 1,
  "backupType": "Daily",
  "createdAtUtc": "2026-10-28T09:30:00.0000000+00:00",
  "createdAtLocal": "2026-10-28T17:30:00.0000000+08:00",
  "schemaVersion": 1,
  "databaseFileName": "notes.db",
  "databaseSizeBytes": 123456,
  "databaseSha256": "64位小写十六进制"
}
```

严格校验：

- `formatVersion` 必须为 1；未知版本拒绝。
- `backupType` 必须是已定义枚举值；JSON 枚举使用字符串，禁止整数。
- `createdAtUtc` 必须为 UTC（偏移 0）；`createdAtLocal` 必须与 UTC 表示同一时刻，可带本地偏移。
- `schemaVersion >= 1`；当前恢复只接受 1。
- `databaseFileName` 必须为 `notes.db`。
- `databaseSizeBytes > 0`。
- `databaseSha256` 必须是 64 位小写十六进制。

manifest 条目读取上限 1 MiB；数据库条目解压/读取上限默认 4 GiB（`BackupPackageVerifier.DefaultMaxDatabaseBytes`）。

### 3.4 快照、校验与发布

```text
源库（只读连接） --SQLite Online Backup API--> 临时 snapshot.db
  -> integrity_check / foreign_key_check / user_version
  -> 计算 notes.db 大小与 SHA-256，写 manifest
  -> 写临时 ZIP（manifest.json + notes.db）
  -> 重新打开 ZIP：条目白名单/重复检查/manifest 校验/大小/SHA-256
  -> 解压数据库（新文件）：integrity_check / foreign_key_check / user_version
  -> 原子移动为最终 ZIP
  -> 清理临时目录与临时文件
```

- 快照目标必须是新文件；已存在目标或 `-journal`/`-wal`/`-shm` 时拒绝，不删除既有文件。
- 包先写 `.quicknotes-package-<guid>.tmp`，校验通过后才 `File.Move`；最终包不覆盖已有文件。
- 发布前的失败或取消不产生最终包；发布后视为操作完成，不因随后取消谎报失败。
- 已有备份不被覆盖；源库保持可用。
- 校验可在不解压 SQLite 的情况下只比对条目大小/SHA-256（调度档），也可完整解压并执行完整性检查（创建与恢复档）。

## 4. 自动备份留存与状态

### 4.1 目录扫描

- 调度档：枚举 `quicknotes-*.zip`，校验 ZIP 结构、manifest、数据库条目长度；用于判断今日是否已有有效日备份。
- 留存档：额外校验数据库条目 SHA-256；不重复解压 SQLite（创建时已做完整校验）。
- 无效包进入 `Issues`，不参与调度/留存删除。

### 4.2 变更指纹

```text
schema=<user_version>;
notes=<COUNT(notes)>;
tags=<COUNT(tags)>;
note_tags=<COUNT(note_tags)>;
categories=<COUNT(categories)>;
tag_name_lengths=<SUM(LENGTH(tags.name))>;
category_name_lengths=<SUM(LENGTH(categories.name))>;
modified=<MAX(notes.modified_at_utc) 或空字符串>
```

指纹在只读连接、deferred 事务内查询。它是启发式：标签/分类重命名或删除若计数和长度和、最大修改时间都不变，可能漏检。

### 4.3 状态文件

`<backupDirectory>/.quicknotes-backup-state.json`：

```json
{
  "formatVersion": 1,
  "lastSuccessfulFingerprint": "schema=1;notes=2;tags=1;note_tags=1;categories=1;tag_name_lengths=5;category_name_lengths=4;modified=2026-10-28T09:30:00.0000000+00:00",
  "lastSuccessfulDailyAtUtc": "2026-10-28T09:30:00+00:00",
  "lastSuccessfulDailyLocalDate": "2026-10-28"
}
```

- 原子写入（临时文件 + `File.Move(overwrite: true)`，落盘后切换）。
- 缺失、不可读、JSON 损坏或字段非法：视为无基线；在当日无有效日备份时，下一次检查会备份（安全优先）。
- 指纹相同且状态对应的日备份仍有效：跳过，不生成重复日备份。
- 状态写入失败：备份仍算成功，返回 `state_write_failed` 警告，下一次可能重复备份。

### 4.4 留存规则

- 保留最近 **7 个本地日历日期**各一份最新有效日备份。
- 额外保留最近 **4 个不同 ISO 周**（周一为一周开始）各一份该周最新有效日备份。
- 两者取并集；同一文件兼任日/周只保留/计数一次。
- 手动备份、无效包、未知类型不自动删除。
- 只在新日备份成功并通过校验后清理；新包始终受保护。
- 删除失败逐文件记录 `retention_delete_failed` 警告并继续，不影响备份成功。

## 5. 恢复协议

```text
预检（只读）
  -> 校验包/条目/manifest/SHA-256/数据库完整性/外键/schema
  -> 当前库存在且可读；无 -wal/-shm；当前目录与备份目录可写
  -> 检查空间、草稿；草稿未允许则阻止
  -> 获取共享写入门（等待在途保存）
  -> 准备当前库（读写打开恢复热 journal；拒绝 WAL sidecar）
  -> 创建 Manual 保护快照并验证
  -> 在当前库同卷创建 .quicknotes-restore-<guid>/：
       恢复库 restored.db；切换时生成回退副本 rollback.db
  -> 提取包内 notes.db 并完整校验
  -> 切换前取消检查
  -> File.Replace(restored.db, current, rollback.db)
  -> 以当前库 SHA-256 + integrity/外键/schema/counts 核对
  -> 成功：清理 staging/回退副本，保留保护快照
  -> 失败：File.Replace(rollback, current, failed) 回退
       -> 回退成功：失败结果 + RolledBack=true
       -> 回退失败：BlockWrites + WritesBlocked=true，保留保护/回退/staging，给出恢复提示
```

- 恢复只接受 schema v1；不迁移、不半迁移。
- 恢复不修改草稿目录或 `.quicknotes-backup-state.json`；备份目录配置与设备设置当前未建模，包/恢复不涉及这些内容。
- 当前库必须存在；首次运行/当前库缺失的恢复未实现。
- 写入门保证恢复与保存在进程内互斥；回退失败后后续保存返回 `StorageUnavailable` + `database_writes_blocked`。

## 6. 兼容性与限制

- schema 版本、备份格式版本、草稿格式版本、状态格式版本均为 **1**；未知版本拒绝。
- 不启用 WAL；当前库存在 `-wal`/`-shm` 时恢复预检/切换拒绝。
- 单进程假设；无跨进程备份/恢复锁。
- 备份包未加密；不含草稿、窗口布局、应用设置、设备专属配置。
- `File.Replace` 依赖 Windows 与同卷 staging；跨卷恢复不支持。
- 真实磁盘满、ACL、进程崩溃的故障矩阵未在当前测试环境执行，见测试报告“未运行”。
