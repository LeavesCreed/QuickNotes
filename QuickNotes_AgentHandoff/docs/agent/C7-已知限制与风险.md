## 4. 产品与工程范围

- **未实现：** TXT/Markdown/JSON/ZIP 导出、安装器/卸载、OS 系统通知、自动更新、云存储、备份加密、增量/分片备份。
- **未支持：** WAL、多实例/跨进程写入锁；当前单进程/单实例假设。
- **备份边界：** 备份包未加密，只含 `notes.db` + manifest；草稿、设备设置、迁移保护快照不进入备份。
- **恢复边界：** 同卷 staging/`File.Replace`；跨卷恢复不支持；回退失败会持久阻断写入，解除需显式验证/人工处理；重启不自动解除。
- **UI 边界：** 真实托盘常驻、真实热键冲突/输入法、混合 DPI、休眠唤醒、UI 级恢复视觉仍有未执行项；C5-M 用户确认不等于 C6 UI 级恢复检查。
- **试用构建：** 未签名、无安装器；框架依赖需要 WindowsDesktop Runtime 10.0.x；自包含约 183 MB；只应按指南使用临时数据根。
- **安全边界：** 备份未加密，不应放入真实生产数据；诊断日志可能包含路径/错误码，不应公开分享真实用户数据。

## 5. 技术选型风险

- `.NET 10 + WPF + SQLite` 的核心数据/恢复闭环与 Windows 桌面行为已有 C1–C6 证据，但 **C6 真实故障/2h/A-11/UI 级恢复检查未关闭**，因此 C7 结论是 **附条件保留**，不是冻结。
- SQLite 单进程/rollback journal 假设满足当前原型；若产品需要多实例、WAL、云同步或超大库，需要重新评估锁、备份和恢复协议。
- 首次冷启动与 Release 性能未纳入门禁；若产品对启动尾部敏感，需要产品确认预算并补测。

## 6. 下一阶段建议

1. 关闭 C7-B01–B04：2h 长稳、真实 VHD/ACL、A-11、UI 级 M02/M03；或在 C7 评审中书面风险接受。
2. 用 Release 试用构建重跑 UI 启动门禁，决定是否另立首次冷启动预算。
3. 补 C5-M 逐项日志/截图（至少托盘、热键、HKCU Run、多屏/DPI、休眠唤醒）。
4. 若进入发布阶段，另立范围：安装器/卸载、签名、备份加密、导出、OS 通知、自动更新、WAL/多实例评估。
5. 保持“试用构建≠发行版”的表述；任何生产代码变更后重跑全量、漏洞审计、WPF 冒烟与相关 C6/C7 门禁。
