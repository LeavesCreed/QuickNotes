## 4. 关键行为

### 4.1 保存结果与错误

- `SaveResult` 携带状态、权威便签、冲突双方、草稿处置、尝试次数与可诊断错误码。
- 原始 `SqliteException` 不再越过 Application：统一翻译为 `NoteStorageException` 子类。
- 输入校验失败 `Attempts=0`；数据库约束/冲突/提交未知计入实际尝试次数。
- 非 BUSY/LOCKED 错误、约束错误、冲突、提交未知均不自动重试。

### 4.2 重试与提交未知

- 默认最多 3 次尝试，退避 50ms/150ms；只重试 `StorageUnavailableException.IsRetryable`（BUSY/LOCKED）。
- 提交使用 `CancellationToken.None`；提交异常包装为 `SaveOutcomeUnknownException`。
- 提交未知后使用新连接回读核验：
  - 状态一致 → `Saved`，继续草稿清理；
  - 版本仍为期望值 → `StorageUnavailable(CommitFailedNotSaved)`，不报成功；
  - 版本/内容不一致或读取失败 → `OutcomeUnknown`，绝不报成功；
  - 行不存在 → 对应 `NotFound`。
- 回滚失败不覆盖原始保存结果，诊断写入 `rollback_error` 并进入 `SaveError.Diagnostics`。

### 4.3 草稿保护

- 成功后才读取草稿；内容完全一致才删除。
- 内容/NoteId/标签集合不一致 → 保留草稿并返回 `DraftMismatch`。
- 草稿不存在 → `AlreadyAbsent`；读取/删除失败 → `CleanupFailed`；保存未成功 → 保留。
- 生命周期操作不接收草稿 ID、不删除草稿。
- 文件存储使用 `<draftId:D>.json`、格式版本 1、原子临时文件替换、SHA 无关的内容校验与稳定错误码；不记录草稿内容到日志。

### 4.4 技术决策

详细背景与取舍见 [ADR：B2 有界 busy 重试改用驱动的秒级 CommandTimeout](../decisions/2026-10-28-b2-bounded-busy-retry.md)。

- Microsoft.Data.Sqlite 10 会在 prepare/step/COMMIT 层按 `CommandTimeout`/`DefaultTimeout` 内部重试 BUSY/LOCKED，默认 30 秒且粒度为整秒。
- 连接字符串 `DefaultTimeout = max(1, ceil(busy_timeout/1000))`，默认 1 秒；保留 `PRAGMA busy_timeout=250ms`。
- 写事务改为显式 deferred，锁冲突落在写步骤。
- 实际单次尝试约 1 秒，3 次加退避最坏约 3.2–3.4 秒；接受该有界行为，950ms 的字面目标不再成立。

- 草稿文件未加密；单进程/单实例假设；无跨进程草稿锁。
