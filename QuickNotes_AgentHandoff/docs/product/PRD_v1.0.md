# Windows 桌面便签软件

## 产品需求规格说明书（PRD）

**版本：** v1.0\
**状态：** 产品需求基线；技术选型尚未冻结\
**目标平台：** Windows 11 x64\
**Windows 10：** 不承诺兼容\
**开发方式：** 使用 AI Agent 辅助开发；软件本身不内置 AI Agent\
**文档目的：** 作为产品需求、技术选型、开发拆分和验收测试的统一依据

------------------------------------------------------------------------

## 1. 文档状态与约定

### 1.1 已确定的产品决策

-   首版 P0/P1/P2 范围已冻结。
-   首版优先支持 Windows 11 x64，不承诺 Windows 10 兼容。
-   三个全局快捷键均可单独修改或禁用。
-   自动备份采用"每日有数据变化时备份"的策略，保留 7 份日备份和 4
    份周备份；手动备份默认不参与自动清理。
-   技术选型尚未最终确定。`.NET 10 + WPF`
    是当前候选方向；编程语言是否采用 C#、是否引入 Rust
    核心，仍属于技术选型讨论，不作为本 PRD 的既定事实。
-   本文中的验收标准描述预期行为；未经实际运行验证的项目不得标记为"测试通过"。

### 1.2 术语

-   **桌面便签：** 独立显示在 Windows 桌面上的单张便签窗口。
-   **管理中心：** 集中查看、编辑和整理全部便签的主管理窗口。
-   **隐藏：** 只改变桌面显示状态，不删除便签内容。
-   **归档：** 将便签从日常列表和桌面移出，但保留其内容及元数据。
-   **回收站：** 保存已删除但尚未永久删除的便签。
-   **全局隐藏：**
    暂时隐藏当前应显示的便签，不覆盖单张便签原有的显示意图。
-   **完整备份：** 用于恢复便签库和必要设置的备份，不等同于 JSON 导出。

## 2. 产品定位与目标

### 2.1 产品定位

开发一款轻量、稳定、可长期使用的 Windows
桌面便签软件。产品由三个主要部分构成：

1.  **独立桌面便签：** 快速记录、查看和编辑内容。
2.  **主管理窗口：** 集中搜索、整理、编辑和回顾便签。
3.  **系统托盘：** 常驻运行、快速操作和明确退出。

### 2.2 核心目标

-   支持同时使用约 5--20 张桌面便签。
-   支持长期积累、搜索、分类、标签和回顾更多历史便签。
-   支持可靠自动保存、备份、恢复和导出。
-   窗口、托盘和快捷键行为符合 Windows 使用习惯。
-   不要求用户登录在线账户即可使用核心功能。
-   不在软件内置 AI Agent；AI Agent 是开发过程中的工具。

### 2.3 非目标

-   第一版不提供无限画布。
-   第一版不内置 AI 写作、总结或智能分类。
-   第一版不提供多级嵌套主分类。
-   第一版不提供便签透明度调节。
-   第一版不提供 JSON/TXT/Markdown 的结构化导入。
-   第一版不承诺 Windows 10 兼容。

## 3. 首版功能范围与优先级

### 3.1 P0：第一版必须实现

1.  独立便签的创建、编辑、移动、缩放、隐藏和置顶。
2.  标题可选、多行纯文本正文、自动保存和草稿保护。
3.  桌面便签与管理中心之间的内容同步及冲突保护。
4.  主管理窗口三栏布局、列表、右侧直接编辑、搜索、筛选、排序和定位。
5.  主分类、副标签、颜色及字号配置。
6.  多选、批量操作和整体撤销。
7.  创建副本、归档、回收站及恢复。
8.  Windows 任务栏、Alt+Tab、托盘、启动、窗口关闭和退出规则。
9.  三个可修改或禁用的全局快捷键。
10. 自动备份、手动备份和安全整库恢复。
11. 单张及批量 TXT/Markdown 导出、便签库 JSON 导出。
12. 后台导出、文件名冲突处理、失败通知和结果记录。
13. 多显示器、DPI、异常退出恢复、升级安全及发布验收。

### 3.2 P1：首版稳定后增强

-   管理中心卡片／网格视图。
-   独立便签概览窗口。
-   更丰富的任务历史管理。
-   更多高级操作个性化。

### 3.3 P2：未来版本

-   多级嵌套主分类。
-   桌面便签自动排列及整体布局撤销。
-   全局和单张透明度。
-   TXT、Markdown、JSON 结构化导入。

### 3.4 范围冻结原则

-   不随意将 P1/P2 功能追加到首版。
-   修复数据安全问题、消除需求冲突和补充必要验收条件，不视为扩大功能范围。
-   技术设计可以预留扩展点，但不能为了未来功能显著增加首版复杂度。

## 4. 便签内容与外观

### 4.1 内容模型

-   标题可为空。
-   正文采用多行纯文本。
-   新建便签后直接聚焦正文。
-   没有手动标题时，列表使用正文首个非空行作为显示标题。
-   标题和正文均为空时，列表显示"无标题便签"。
-   标题、正文、分类、标签、外观、显示状态及窗口布局均应按规则自动保存。

### 4.2 默认位置与尺寸

-   手动新建便签默认在现有便签附近错位排列。
-   新窗口不得完全位于屏幕外或不可访问区域。
-   默认尺寸、最小尺寸和具体字号范围属于待技术原型确认的参数。
-   窗口位置、尺寸和显示器信息必须在合理范围内持久化。
-   显示器断开或分辨率变化后，便签必须可以被找回。

### 4.3 置顶

-   每张便签独立设置置顶，默认不置顶。
-   置顶仅影响窗口层级，不改变其他便签的状态。
-   从管理中心定位便签不得擅自改变其置顶属性。

### 4.4 颜色与字号

-   主分类提供默认颜色。
-   便签可以手动选择颜色，也可以恢复跟随主分类。
-   修改主分类默认颜色时，仍跟随分类颜色的便签自动更新；手动选择过颜色的便签保持原样。
-   分类默认颜色更改时，跟随该分类的便签采用新的浅紫色默认值（按已确认的产品规则）。
-   字号支持全局默认与单张便签覆盖。
-   顶栏自定义采用全局统一配置：调整一次后，所有便签顶栏采用相同配置。
-   用户可以将"更多"菜单中的可用操作添加到顶栏。
-   第一版不支持透明度调节。

## 5. 窗口、显示与生命周期状态

### 5.1 单张隐藏

-   点击便签右上角 X 只隐藏当前便签。
-   隐藏不等于归档或删除。
-   隐藏不改变内容、分类、标签、颜色、字号或置顶状态。
-   重新显示主要通过管理中心完成。

### 5.2 全局隐藏

-   全局隐藏暂时隐藏当前应显示的便签。
-   不覆盖单张便签的独立显示意图。
-   全局恢复只恢复原本应显示的便签。
-   全局隐藏期间，用户可以单独显示某张便签；此操作不应恢复其他便签。
-   全局隐藏状态在正常退出和重新启动后的恢复规则应一致。

### 5.3 业务生命周期

便签的业务状态分为：

-   正常。
-   已归档。
-   回收站。

桌面显示状态与业务生命周期独立保存，不得把隐藏误判为归档或删除。

### 5.4 归档

-   归档后从日常列表和桌面移出。
-   归档保留便签内容和全部元数据。
-   立即撤销归档时恢复归档前状态。
-   日后手动取消归档时，回到正常列表，但默认保持桌面隐藏。
-   普通搜索默认不包含归档便签。
-   搜索栏提供"包含归档"快捷选项；开启后合并显示归档结果，并以明确标记区分归档便签。
-   归档标记属于系统状态，不应与普通用户标签混淆。

### 5.5 删除与回收站

-   普通删除不弹出二次确认，直接移入回收站。
-   删除后提供即时撤销。
-   回收站完整保留便签元数据。
-   回收站默认长期保留；用户可主动开启自动清理期限。
-   从回收站恢复时保留内容和组织信息，默认隐藏桌面窗口。
-   永久删除或清空回收站需要明确确认。
-   不得因删除、恢复或清理操作静默丢弃未保存正文。

### 5.6 创建副本

-   副本拥有独立 ID 和独立内容。
-   复制正文、主分类、副标签及适用的外观设置。
-   有手动标题时自动追加"（副本）""（副本 2）"等编号。
-   原便签没有手动标题时，副本标题保持为空。
-   创建副本后立即显示新副本，错位排列并聚焦正文。
-   副本未修改时，撤销创建直接将其移入回收站。
-   副本已修改时，撤销创建需要确认后移入回收站。
-   撤销创建不影响原便签，也不直接永久删除副本。

## 6. 分类、标签与整理

### 6.1 主分类

-   每张便签恰好属于一个主分类。
-   第一版主分类为扁平结构。
-   系统保留"未分类"，不可删除。
-   删除普通主分类时，默认将其中便签移至"未分类"。
-   用户可以指定其他目标主分类。
-   提供批量移动到其他主分类的功能。
-   数据结构应为未来多级分类预留合理扩展空间，但首版不实现多级分类。

### 6.2 副标签

-   每张便签可以有零个或多个副标签。
-   编辑便签时可选择已有标签，也可直接创建标签。
-   标签输入无匹配项时提供"创建"选项。
-   重命名标签更新全部关联便签。
-   重命名到已有标签时必须明确确认合并。
-   删除标签不删除便签，只解除标签关联。
-   批量添加标签不移除其他标签；批量移除只移除用户指定的标签。

### 6.3 标签筛选

-   首版采用已确认的方案 A。
-   多标签筛选首版按匹配任一所选标签的 OR 逻辑处理。
-   架构预留未来增加 AND 筛选的空间，但 AND 筛选不属于首版交付要求。
-   标签筛选不得改变便签所属主分类。

## 7. 主管理窗口

### 7.1 布局

-   左侧：全部便签、主分类、副标签、归档、回收站等导航。
-   中间：搜索、筛选、排序、列表及多选操作。
-   右侧：当前便签的直接编辑面板。
-   右侧面板默认显示。
-   窗口空间不足时自动折叠，用户也可以手动显示或隐藏。

### 7.2 列表行为

-   单击列表项：选中，并在右侧直接编辑。
-   双击列表项：定位到桌面便签。
-   定位可将目标带到其所属窗口层级前方，并短暂高亮。
-   定位不擅自修改便签内容、置顶、分类或标签。
-   对单独隐藏的便签，定位操作应显示并激活目标。
-   列表默认按最后修改时间倒序。
-   编辑期间暂缓重新排序；编辑结束后按最新修改时间更新。

### 7.3 搜索与筛选

-   支持标题、正文及标签关键词搜索。
-   支持主分类、标签和日期等筛选。
-   普通搜索默认不包含归档；通过"包含归档"选项扩展搜索范围。
-   回收站使用独立入口，不混入普通搜索结果。
-   归档结果须有明确的视觉标记。
-   搜索结果遵循单击编辑、双击定位的规则。

### 7.4 多选与批量操作

-   管理中心提供独立多选模式。
-   支持批量移动主分类、添加或移除标签、归档和移入回收站。
-   批量操作成功后保持多选模式，但清空已选项。
-   失败或取消时，不按成功操作清空选择。
-   一次批量操作作为一个完整操作撤销。
-   右键已选中便签时，菜单针对全部已选便签。
-   右键未选中便签时，只操作该便签，不改变原选中集合。
-   列表行尾 ⋯ 菜单始终只操作当前单张便签，不改变其他多选状态。
-   搜索或筛选结果变化导致选择对象不可见时，应清理无效选择，避免不可见对象意外参与批量操作。

### 7.5 修改与撤销

-   批量操作撤销应恢复每张便签各自的原值。
-   管理操作撤销与正文编辑框中的 Ctrl+Z 必须区分。
-   撤销不能覆盖撤销目标操作之后发生的独立修改。

## 8. Windows 窗口与系统托盘

### 8.1 任务栏与 Alt+Tab

-   只有主管理窗口显示任务栏入口并参与 Alt+Tab。
-   独立便签不显示在任务栏或 Alt+Tab。
-   独立便签仍可以通过桌面点击、管理中心定位等方式激活。
-   主管理窗口最小化或隐藏时，独立便签继续按各自状态显示。

### 8.2 主管理窗口最小化与关闭

-   最小化按钮：最小化到 Windows 任务栏。
-   点击右上角 X：弹出"关闭应用""缩小到系统托盘""取消"三个选项。
-   "缩小到系统托盘"只隐藏管理中心，程序继续运行。
-   "取消"不执行关闭或隐藏操作。
-   只有用户明确选择"关闭应用"或托盘菜单中的"退出软件"才真正退出程序。

### 8.3 系统托盘

-   托盘左键单击：打开或激活主管理窗口。
-   托盘右键：显示操作菜单。
-   菜单应提供新建便签、全局显示／隐藏、管理中心、设置和退出软件。
-   关闭管理中心不等于退出软件。
-   托盘中应只有一个运行实例对应的入口。

### 8.4 启动

-   Windows 登录自动启动默认关闭，用户可开启。
-   登录自动启动时恢复应显示的桌面便签，主管理窗口保持隐藏。
-   手动启动时恢复应显示的便签并打开主管理窗口。
-   软件已运行时再次启动应激活现有实例，不创建第二实例。
-   首次引导完成后显示空白桌面和新建入口，不自动创建便签。

### 8.5 多显示器与 DPI

-   支持 Windows 11 x64 多显示器桌面环境。
-   显示器断开、分辨率变化或缩放比例变化后，窗口必须可以找回。
-   窗口不得永久恢复到不可见区域。
-   混合 DPI 环境下文字应保持可读，控件应保持可操作。
-   窗口找回不得无故改变便签内容、分类或置顶状态。

## 9. 全局快捷键

第一版包含三个全局快捷键，每个均可单独修改或禁用。

  功能                     建议默认组合（尚待原型验证）
  ------------------------ ------------------------------
  新建便签                 Ctrl+Alt+N
  打开主管理窗口           Ctrl+Alt+M
  全局隐藏／恢复桌面便签   Ctrl+Alt+H

规则：

-   快捷键注册失败时必须明确提示，不得显示为已启用。
-   允许用户修改或禁用单个快捷键。
-   必须处理快捷键与其他程序或系统功能的冲突。
-   全局快捷键不得破坏普通文本输入和中文输入法组合输入。
-   全局隐藏／恢复必须遵守单张便签的独立显示意图。
-   默认组合是建议值，最终需通过 Windows 原型验证。

## 10. 自动保存、同步与异常恢复

### 10.1 自动保存

-   标题、正文、分类、标签、颜色／字号模式、显示状态和窗口布局按规则自动保存。
-   UI 应区分编辑中、保存中、已保存和保存失败状态。
-   保存失败必须持续可见，不能短暂提示后无痕消失。
-   保留未写入正文和可恢复草稿，并提供重试入口。
-   不得因为隐藏窗口、归档或退出而无提示丢弃未保存内容。

### 10.2 同时编辑

-   同一便签可在桌面窗口和主管理窗口中编辑。
-   两处修改应同步到同一权威数据源。
-   旧保存请求不得覆盖更新版本。
-   不应因同步而无故重置光标、选区或中文输入法状态。
-   发生冲突时保留双方内容并提供处理入口，不允许静默覆盖。

### 10.3 异常退出

-   重新启动时检查上次是否异常退出及是否存在可恢复草稿。
-   已成功保存的数据正常恢复。
-   更近的未保存草稿应保留并提供恢复入口。
-   草稿与正式数据冲突时先保留两者。
-   异常恢复不得无条件重新显示所有原本隐藏的便签。

------------------------------------------------------------------------

## 11. 备份与恢复

### 11.1 首次配置

-   首次运行要求用户选择备份目录，但允许取消并进入软件。
-   用户跳过时，明确提示备份尚未配置。
-   在选择有效目录之前不启用自动备份。
-   主数据目录与备份目录应分离。
-   配置目录时验证可访问性和写入能力。

### 11.2 自动备份频率

**已确定：每日有数据变化时备份。**

-   以本机当地日历日为单位。
-   当日数据发生有效变化后，在适当的后台时机执行备份。
-   当日无数据变化时，不生成不必要的重复日备份。
-   正常情况下同一日保留一份成功的自动日备份。
-   备份失败不能标记为当天已成功；修复问题后允许重试。
-   软件连续运行跨越日期时仍应检查新一天的备份需求。
-   软件未运行时不要求额外常驻进程；下次启动后检查是否需要执行，不为停机期间每一天补造空备份。
-   备份基于一致的数据快照，不应破坏正在进行的编辑。

### 11.3 自动备份留存

**已确定：保留 7 份日备份和 4 份周备份。**

-   保留最近 7 份有效自动日备份。
-   额外保留最近 4 个有成功备份的不同周所对应的代表性备份。
-   周备份可以从当周已校验成功的日备份中选取，不要求重复写入同一份数据。
-   同一物理文件兼作日备份和周备份时不重复计数。
-   没有成功备份的日期或周不得生成虚假记录。
-   先确认新备份成功并通过校验，再清理超出留存范围的旧自动备份。
-   清理失败不得影响源数据。
-   不得提前删除唯一已知有效的恢复点。

### 11.4 手动备份

-   支持用户主动创建完整备份。
-   手动备份保留独立记录。
-   手动备份默认不参与自动轮换清理。
-   用户主动删除手动备份时，应明确确认。
-   手动备份同样需要完整性验证。

### 11.5 备份内容

完整备份至少包括：

-   正常、归档和回收站便签。
-   标题、正文、创建与修改时间及唯一 ID。
-   主分类、标签定义及关联关系。
-   颜色、字号及默认／覆盖模式。
-   显示、隐藏、置顶、位置和尺寸。
-   全局隐藏恢复所需状态。
-   应用恢复业务行为所需的设置及顶栏配置。
-   备份格式和数据模式版本。
-   完整性校验所需信息。

当前设备专属配置，例如当前备份目录、系统开机启动注册状态和具体显示器标识，跨设备恢复时必须重新适配，不能盲目覆盖。

### 11.6 整库恢复

第一版只提供整库恢复，不提供复杂的跨备份自动合并。

恢复前必须：

1.  检查备份文件是否存在且可读。
2.  检查完整性和校验信息。
3.  检查格式及数据模式版本兼容性。
4.  检查便签、分类、标签关联的结构完整性。
5.  检查可用空间和写入权限。
6.  检查未保存草稿、冲突及正在执行的写入任务。
7.  在覆盖当前数据前创建保护快照。

恢复确认界面显示备份时间、来源、版本、正常／归档／回收站数量、分类标签数量，以及当前数据库将被整库替换的明确说明。

### 11.7 恢复执行与失败回退

-   先准备临时恢复数据并完成校验，再安全切换。
-   恢复过程中避免与数据库切换冲突的写入。
-   预检查失败时原库不变。
-   准备阶段失败时清理或隔离临时数据，原库保持可用。
-   切换失败时通过保护机制回退。
-   回退失败时停止继续写入，保留原始数据库和保护文件，并提供明确处理指引。
-   任何失败不得被记录为恢复成功。
-   恢复成功后核对便签数量、内容和分类标签关联。
-   恢复后窗口应按当前显示器条件安全找回。
-   当前设备的备份目录配置继续保留。
-   恢复来的全局快捷键必须在当前机器重新验证；系统开机启动状态不得被其他设备的备份盲目覆盖。

### 11.8 升级保护

-   数据模式迁移前创建保护快照。
-   升级失败不得让半迁移数据库被当作正常数据使用。
-   升级不得清空便签、分类、标签、窗口布局或用户设置。
-   升级后不重新执行首次安装引导。

## 12. 数据导出

### 12.1 格式与组织

-   支持单张 TXT、单张 Markdown。
-   支持批量 TXT、批量 Markdown。
-   支持整个便签库 JSON 结构化导出。
-   批量 TXT/Markdown 导出使用 ZIP，并按主分类建立子目录。

### 12.2 JSON 范围

-   默认包含正常和归档便签。
-   回收站通过独立选项勾选，默认不包含。
-   包含恢复或迁移所需的便签内容及相关元数据。
-   JSON 导出不是完整应用备份，不能替代完整备份恢复。

### 12.3 文件重名

目标文件已存在时提供三个选项：

1.  保留两个文件。
2.  覆盖现有文件。
3.  取消导出。

默认推荐"保留两个文件"。

-   不得静默覆盖。
-   ZIP 内部重名文件应安全编号。
-   覆盖时先生成并校验新文件，再安全替换旧文件。
-   失败时尽可能保留原有目标文件。

### 12.4 后台导出

-   导出基于一致的数据快照。
-   管理中心最小化或隐藏时，导出继续。
-   导出期间不影响其他便签正常编辑。
-   成功、失败和取消均保留任务结果。
-   成功默认静默；失败发送 Windows 系统通知。
-   不完整文件不得标记为成功。

### 12.5 导出期间退出

如果真正退出时存在未完成导出任务，提供：

1.  导出完成后退出。
2.  取消导出并退出。
3.  返回软件。

-   选择完成后退出：导出成功且未保存数据检查通过后退出。
-   导出失败时不自动退出，保留错误记录。
-   取消导出并退出时安全停止任务并清理临时文件，不损坏已有目标文件。
-   返回软件时任务继续执行。
-   即使导出已完成，退出前仍须执行必要的数据安全检查。

## 13. 错误反馈与通知

### 13.1 一级：保存风险

适用于自动保存失败或持续写入失败。

-   相关界面持续显示高优先级警告。
-   保留未保存内容和可恢复草稿。
-   提供重试入口。
-   尝试发送 Windows 系统通知。
-   问题未解决前不得虚假显示为已保存。

### 13.2 二级：后台任务失败

适用于自动备份失败和数据导出失败。

-   发送 Windows 系统通知。
-   管理中心保留失败时间、原因、结果和处理入口。
-   对重复持续发生的同类错误进行通知去重。

### 13.3 三级：正常完成

自动保存、备份和导出成功等正常完成事件默认不发送 Windows 通知。

### 13.4 通知设置

-   用户可以控制 Windows 系统通知。
-   关闭通知不隐藏应用内部错误状态和历史记录。
-   尊重 Windows 通知权限及免打扰设置。
-   不得为了显示通知而强制抢夺用户当前焦点。

## 14. 全局快捷键与编辑快捷键

### 14.1 全局快捷键

  功能                 建议默认组合
  -------------------- --------------
  新建便签             Ctrl+Alt+N
  打开主管理窗口       Ctrl+Alt+M
  全局隐藏／恢复便签   Ctrl+Alt+H

每项可单独修改或禁用；默认组合需通过 Windows 原型验证后最终确认。

### 14.2 管理中心局部快捷键（建议）

-   Ctrl+N：新建便签。
-   Ctrl+F：聚焦搜索框。
-   Esc：关闭当前菜单或取消当前可取消的交互。
-   Ctrl+Z：在正文编辑框中撤销文本输入。

正文撤销与管理操作撤销必须区分。

## 15. 技术选型状态与架构约束

### 15.1 当前状态

-   产品需求已形成基线。
-   `.NET 10 + WPF` 是当前 Windows 原型的候选方向。
-   C# 与 Rust 的最终职责划分尚未确定。
-   SQLite 是当前数据存储候选方向，尚待技术验证。
-   安装包、更新机制和发布工具尚未确定。

### 15.2 架构约束

不论最终技术栈如何选择，必须满足：

-   界面与业务规则有明确边界。
-   数据持久化有唯一权威写入路径。
-   自动保存、批量操作、备份、恢复和导出可独立测试。
-   窗口状态不直接决定便签业务生命周期。
-   备份和恢复不依赖界面窗口一直打开。
-   技术选型不得降低本 PRD 已确定的数据安全要求。

## 16. Windows 兼容范围

### 16.1 正式支持目标

-   第一版目标为 Windows 11 x64。
-   不承诺 Windows 10 兼容。
-   应在开发和发布时，对当时仍受支持的 Windows 11 x64 版本进行实际测试。
-   不在未经测试的情况下承诺 Windows on ARM、Windows Server
    或其他特殊环境。

### 16.2 系统集成验收

必须实际验证：

-   独立便签不显示在任务栏和 Alt+Tab。
-   管理中心显示正确的任务栏和 Alt+Tab 入口。
-   管理中心隐藏或最小化不影响独立便签。
-   置顶和普通窗口层级正确。
-   托盘只有一个有效实例入口。
-   全局快捷键可注册、修改、禁用，并能检测冲突。
-   Windows 通知权限和免打扰设置得到尊重。

### 16.3 显示器和 DPI 验收

测试覆盖：

-   单显示器与多显示器。
-   显示器断开和重新连接。
-   100%、125%、150%、200% 缩放。
-   分辨率和工作区变化。
-   在不同缩放比例的显示器之间移动窗口。
-   原显示器不再存在时恢复窗口。

## 17. 安装、升级与卸载

### 17.1 安装

-   第一版应提供普通用户可使用的安装方式，不要求用户配置开发环境。
-   MSI、EXE 安装器或 MSIX 尚未决定。
-   安装完成后不强制开启开机启动。
-   首次引导允许跳过备份目录配置。

### 17.2 升级

-   保留便签、分类、标签、外观、窗口布局和用户设置。
-   数据模式变化时先创建保护快照并验证迁移。
-   更新失败时可回退或安全恢复。
-   不把普通升级当作首次安装重新引导。

### 17.3 卸载

-   建议默认保留用户便签数据及外部备份。
-   卸载界面应清楚说明数据是否保留。
-   删除本地数据或备份必须由用户明确选择并确认。
-   不应将卸载软件自动等同于永久删除全部便签。

## 18. 核心验收测试清单

### 18.1 窗口与托盘

-   [ ] 同时显示 20 张便签时，便签不出现在任务栏和 Alt+Tab。
-   [ ] 管理中心最小化后，独立便签保持显示。
-   [ ] 点击管理中心 X 时出现"关闭应用／缩小到系统托盘／取消"。
-   [ ] 缩小到托盘后进程继续运行，便签状态不变。
-   [ ] 托盘左键可打开管理中心，右键可打开操作菜单。
-   [ ] 再次启动应用时激活现有实例，不创建第二实例。
-   [ ] 开机启动时恢复应显示便签，管理中心保持隐藏。
-   [ ] 全局隐藏与恢复不会改变单张隐藏状态。
-   [ ] 全局隐藏期间可以单独显示目标便签。
-   [ ] 置顶属性独立有效。
-   [ ] 显示器断开后窗口可安全找回。
-   [ ] 快捷键冲突时明确提示，禁用后不再响应。

### 18.2 自动保存与生命周期

-   [ ] 隐藏并重新显示便签后正文不丢失。
-   [ ] 桌面窗口和管理中心交替编辑时数据同步正确。
-   [ ] 模拟写入失败时保留草稿并持续显示警告。
-   [ ] 制造版本冲突时不静默覆盖内容。
-   [ ] 批量操作撤销后每张便签恢复原有属性。
-   [ ] 普通删除可即时撤销。
-   [ ] 回收站恢复保留元数据并默认隐藏桌面窗口。
-   [ ] 已修改副本的撤销创建需要确认。

### 18.3 备份与恢复

-   [ ] 首次跳过备份目录后仍可使用软件，自动备份保持未配置。
-   [ ] 不可写目录不会被标记为有效备份位置。
-   [ ] 数据变化后生成可校验的日备份。
-   [ ] 当日无变化时不生成不必要的重复备份。
-   [ ] 自动备份留存符合 7 份日备份和 4 份周备份规则。
-   [ ] 自动轮换不删除手动备份。
-   [ ] 新备份校验失败时保留已有有效恢复点。
-   [ ] 损坏备份被拒绝，不修改原库。
-   [ ] 恢复中断或失败时能够保留或回退原数据。
-   [ ] 恢复后便签数量、内容、分类和标签关系一致。
-   [ ] 跨设备恢复不会盲目覆盖当前设备备份目录和系统启动状态。

### 18.4 导出与退出

-   [ ] 批量导出按主分类建立 ZIP 子目录。
-   [ ] 目标文件重名时提供保留两个、覆盖和取消三个选项。
-   [ ] 导出失败不修改源便签或误报成功。
-   [ ] 管理中心隐藏后后台导出继续。
-   [ ] 导出成功不发送 Windows 成功通知。
-   [ ] 导出失败发送通知并保留错误记录。
-   [ ] 导出期间退出时显示三个指定选项。
-   [ ] 导出失败时不自动退出。
-   [ ] 退出前检查未保存数据。

## 19. 非功能性与发布验收

### 19.1 稳定性

-   覆盖 5、10、20 张可见便签的常规使用。
-   覆盖至少 1,000 张历史便签的搜索、筛选和列表使用。
-   测试长时间运行、反复显示／隐藏窗口和睡眠唤醒。
-   测试磁盘空间不足、权限不足、备份设备断开、进程异常退出。

### 19.2 性能指标

响应时间、内存占用和长时间运行目标须在技术原型测得基线后确定，不得在未测量时宣称已达标。

### 19.3 发布关卡

1.  **需求关卡：** 所有 P0 功能有明确行为定义，P1/P2 不混入首版。
2.  **数据安全关卡：**
    自动保存、备份、恢复和导出异常测试通过，无已知数据丢失类阻断问题。
3.  **Windows 关卡：** 窗口、托盘、快捷键、多显示器和 DPI 测试通过。
4.  **稳定性关卡：** 常规窗口操作、长期运行和大量历史便签测试通过。
5.  **升级关卡：** 新装、升级、迁移失败、卸载和数据保留行为测试通过。
6.  **发布资料关卡：**
    安装包、版本说明、支持范围、备份恢复指南、已知问题和验收记录齐全。
