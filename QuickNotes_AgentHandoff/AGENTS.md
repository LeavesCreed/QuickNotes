# AGENTS.md --- 项目级开发规则

## 项目目标

构建高质量、可长期使用的 Windows 11 x64 桌面便签软件。AI Agent
是开发工具，不是产品内置功能。

## 开始前必须阅读

1.  `docs/product/PRD_v1.0.md`
2.  `docs/agent/Agent对接文档_B阶段.md`
3.  `agent.md`
4.  本文件及相关 `docs/decisions/` 决策记录

若文件缺失，先报告，不要凭摘要重建需求。

## 已确认约束

-   正式目标平台是 Windows 11 x64；不承诺 Windows 10 兼容。
-   PRD v1.0 是产品行为权威来源；不得擅自修改已确认规则或扩大首版范围。
-   数据安全、可恢复性和明确错误反馈优先于开发速度。
-   未实际运行的测试必须标记"未运行"，不能声称通过。
-   隐藏、归档、回收站是不同状态，不可混用。
-   用户优先完成高质量软件，Rust 可以后续引入；当前 B 阶段不引入 Rust
    FFI。

## 技术状态

-   `.NET 10 + WPF` 是当前 Windows 桌面候选方向。
-   B 阶段可暂用 C#、.NET 10、SQLite 做数据原型。
-   该选择仅服务于原型验证，最终技术选型尚未完全冻结。
-   SQLite
    是候选方案，不要在文档中写成已最终确认，除非用户后续明确确认。

## 当前阶段范围

只验证数据存储与备份恢复：数据模型、事务、版本冲突、schema
版本、备份快照、校验、自动留存、恢复预检与回退、故障测试。 不要实现完整
WPF 产品 UI、托盘、快捷键、搜索/分类 UI、安装器或 Rust 集成。

## 推荐模块边界

-   `Domain/`：实体、状态、业务约束；不依赖 UI/数据库。
-   `Application/`：保存、备份、恢复用例与接口。
-   `Infrastructure/Sqlite/`：schema、查询、事务、迁移。
-   `Infrastructure/Backup/`：快照、manifest、校验、留存、恢复切换。
-   `Tests/`：单元、集成和故障注入测试。
    保持简单；不要为小原型引入没有明确价值的框架。

## 数据安全硬规则

-   只有事务提交并完成必要验证后才能报告保存成功。
-   不得静默丢弃内容，不得在失败时覆盖/删除唯一有效原始数据。
-   对正在使用的 SQLite 数据库，不得仅复制主 `.db`
    文件并宣称是可靠一致性备份；使用 SQLite
    支持的一致性快照方式，或证明数据库已安全关闭且相关状态文件已正确处理。
-   开启并验证外键约束；schema 变更必须有版本号/迁移机制。
-   恢复先预检、写入临时位置、验证，再切换；失败要保留原库并回退。
-   先确认新备份成功且通过校验，再清理超额自动备份。
-   自动清理不得删除手动备份。
-   处理 ZIP/归档输入时防范路径穿越。
-   所有测试使用合成数据和临时目录，不接触真实用户数据。

## 错误、日志与测试

-   错误需可诊断，不能吞异常或只返回模糊 `false`。
-   日志记录阶段、结果、耗时和错误摘要；默认不记录真实便签正文。
-   正确处理异步异常、取消和资源释放。
-   成功路径和失败路径都要有测试。
-   变更 schema/备份格式/恢复协议时，同步更新文档和测试。
-   每次交付报告修改文件、测试命令、实际结果、已知限制和待决事项。

## 变更管理

-   不得擅自改写 `docs/product/PRD_v1.0.md`。
-   需求歧义先提出问题或写 ADR
    草案并标"待用户确认"，不要把建议冒充决定。
-   技术决策与产品决策分开记录。
-   不要声称已经操作用户机器，除非工具实际执行并提供证据。
